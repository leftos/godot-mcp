# Decisions

The user's decisions and the engine facts behind them, from the first version (2026-09-25 to 2026-09-26), promoted from its plan when it shipped. How the code works now is [ARCHITECTURE.md](./ARCHITECTURE.md); this page is why. A later decision that reverses one here edits it in place and says so.

## Why this server exists

The user's two Godot projects (opening-hand and delve-the-dungeon, both C#, Godot 4.7.2) were driven through the third-party `godot-mcp-runtime` 3.4.0 (npx, TypeScript, MIT), whose costs were recorded across both repos:
- **The bridge is written into `project.godot`**, and `stop_project` has left it there. There is a commit rule in both repos and in the user-level Godot conventions because of it.
- **Simulated input misses.** Motion events carry no `button_mask`, so a drag does nothing (2026-09-25). Clicks land in window pixels while `get_ui_elements` reports viewport pixels, so a letterboxed window misses small buttons. Typed text arrives in lower case.
- **`run_project` passes no arguments**, so delve uses a launch-then-attach workaround.
- **One command at a time**, no request ids, and JSON parsed out of stdout by finding the first bracket.

## Decided (user, 2026-09-25 and 2026-09-26)

1. **Fresh code.** `godot-mcp-runtime` (MIT) and Godot's source are read for reference only; nothing is forked.
2. **The bridge is injected and never committed.** A run loads it through `override.cfg` in the project folder, which is hidden from git through `.git/info/exclude`.
   - Verified 2026-09-25 on 4.7.2: an `override.cfg` autoload pointing outside the project loaded, and `project.godot` was untouched.
   - Godot's source: game runs read `override.cfg`; the editor, `--import` and `--export` never do (`main/main.cpp:2107`, `p_ignore_override`).
3. **C# / .NET 10 server, GDScript bridge.**
4. **Its own repo at `D:\godot-mcp`.**
5. **First-version must-have: faithful input**, offered as gestures plus raw events. Gamepad input is part of it: buttons, sticks and triggers per device (user, 2026-09-25).
6. **The 16 headless scene and node tools are included.**
7. **`run_project` takes pass-through arguments.**
8. **Cutover at parity**, in every project at once; the old registration is removed.
9. **Sixteen friction features, all before the cutover** (user, 2026-09-25, choosing every option offered and "all before cutover" over building only the structural ones first):
   - Time: frame control, `wait_for`, `restart_project`, fresh-worktree prep.
   - Inspection: the running scene tree, `inspect_node`/`set_property`, `call_method`, an error feed on every result, screenshot baselines.
   - Scale: several sessions, a hang watchdog, quiet by default, in-engine recording.
   - Ergonomics: tool annotations, a batch drive tool, compact outputs, project profiles.

   This reversed decision 5's "several sessions" and "in-engine recording" as later work.
10. **Sessions, the error feed, screenshots and quiet runs** (user, 2026-09-25, each the recommended option of a ranked choice):
    - **Session names.** `run_project` and `attach_project` take an optional `session`; without one, the session is named after the project folder. A second session under a live name is refused and asked for a name; a name whose run has exited is replaced. Runs and attaches share one name space. A stopped run is kept until then, for its crash output, a restart by name and a recording's outcome, but `list_sessions` and the session errors show only the live ones, with a count of the stopped (user, 2026-09-27, #11). `stop_project` says a run had ended before it (`alreadyExited`) and gives the game's own exit code beside the wrapper's (user, 2026-09-27, #12). A runtime tool without a name uses the only session, and with several it refuses, listing the names. The refusal and every `session` description tell the agent to pass the session `run_project` or `attach_project` returned on every call from the start, since another agent's game can start at any time; no default session is kept (user, 2026-09-28, #35). One server process serves one client, so the agents in it cannot be told apart, and a default one agent set would send another agent's calls, `stop_project` included, to its game. `list_sessions` (read-only) returns each session's name, project, kind (run or attach), liveness and process id.
    - **Several sessions on one project folder** (delve's server and two clients). The marked `override.cfg` is reference-counted and removed when the last session on that folder ends. Across servers too: its second line lists the server processes (pid and start time) with live sessions on it, a release takes one off and deletes the file only when none is left, and a file whose owners have all exited is stale, removed by a headless run on the folder and by every server's startup sweep of the folders it has written to (the user chose this over leaving the leftover for the bridge to make harmless). A new session whose `shutOutRealGamepads` differs from the live ones' is refused, since the file holds one value. An attach is refused while another attach on the same folder is still waiting for its game.
    - **The five-parameter limit holds.** `session` goes into `run_project`'s `options`; `gamepad_axis` and `gamepad_stick` move `durationMs` and `release` into an `options` object to make room for it.
    - **Error feed.** The bridge registers a `Logger` (`OS.add_logger`, confirmed in 4.7.2's source first) and sends errors with function, file, line and Godot's script backtrace over the wire, so attached games report too. Results carry errors only, in an `errors` array, and the call still succeeds; `get_errors(since)` returns errors and warnings keyed by a per-session sequence cursor.
    - **Screenshots** default to an inline preview at most 480 px wide, plus the full-size path.
    - **Quiet by default** (reshaped by the user on 2026-09-26 after review measured the first build): `run_project` starts quiet unless `options.quiet = false`. The window is created unfocused and off-screen by the quiet run's `override.cfg` (`[display]` `window/size/no_focus` and an off-screen initial position), because Godot creates the main window focused before any script runs (`platform/windows/display_server_windows.cpp` L1970-1973), and un-focusing it later does not release the focus it holds. It stays click-through. Audio is off through `--audio-driver Dummy`, placed before the user's engine arguments, never by touching the game's buses, so the game's own mute stays testable and no muted state leaks into its saved settings. Real input is kept out by the window never receiving it, not by swallowing: an always-on swallow also killed input the game synthesises itself (on-screen keyboards, virtual cursors) and never reached scene `_input` handlers or `Input` polling. The real mouse is still swallowed while a gesture plays, as before. Sessions on one folder must agree on quiet (the override holds one value). An attach is quiet only with `quiet: true` (user, 2026-09-27, #14): the override and the bridge's parking apply, but only a launcher can put a game on the hidden desktop or pass `--audio-driver Dummy`, so a debugger-launched game still shows for a moment at start and needs that argument in its own launch for silence. Real pads stay opt-in through `shutOutRealGamepads`. Ruled out: marking injected keys with the mouse's device mark (a key's device is 16 and the built-in `ui_*` actions match only 16 or -1: `core/input/input_event.cpp` L669-671, `core/input/input_map.cpp` L147-153).
    - **A quiet run caps its frame rate** (user, 2026-09-26, issue #6): the bridge sets `Engine.max_fps` to 60 when the project leaves it at 0. The window keeps VSync however hidden it is (`display_server_windows.cpp` `window_can_draw` L3123-3129 depends only on minimizing), so a quiet run drew at the monitor's 239 Hz. A project's own cap, or a `--max-fps` in `engineArgs`, wins; the bridge cannot tell an explicit 0 from the default. A recording run is unaffected: its fixed fps skips the frame delay (`main.cpp` L5170-5178).
11. **Time, inspection, prep, the watchdog, baselines, profiles and batches** (user, 2026-09-26, each the recommended option of a ranked choice; the rest settled from measurements and the explorers' 4.7.2 citations):
    - **Time.** One `frame_control(action, count, scale, options {unit, screenshot})` tool: pause is `SceneTree.paused` (the bridge is `PROCESS_MODE_ALWAYS`); `step` counts whole frames from one `frame_post_draw` to the next (or physics ticks with `unit: "physics"`), pausing first and leaving the game paused, and can capture on the Nth frame; `time_scale` sets `Engine.time_scale` in (0, 100]. `wait_for(condition, timeoutMs)` takes exactly one of `{node, exists}`, `{node, property, equals}`, `{node, signal}` or `{expression}` (Godot's `Expression` with `node`, `root`, `tree`, `Input`, `Engine`); a timeout (default 10 s, cap 120 s) is a result `{met: false, last}`, not an error; while paused only a signal wait is allowed.
    - **Inspection.** `get_scene_tree` pages a flat depth-first list like `get_ui_elements`; `inspect_node` returns script variables plus editor-visible properties by default. `set_property` and `call_method` convert JSON by the declared type and read back, failing loudly, because Godot's own conversions fail silently (`gdscript.cpp` L1536-1557, `class_db.cpp` L1569-1610, `variant.cpp` L1745-1761). A C# fixture (`tests/fixtures/CsProbe`) proves `call_method` on C# methods.
    - **Restart and prep.** Prep (a missing import cache, a missing or stale C# assembly) runs automatically in `run_project` and `restart_project`, skipped by `options.prepare: "never"`. The build is `dotnet build <csproj> -c Debug -p:GodotTargetPlatform=windows`, not `--build-solutions` (the editor dies on a cold cache, delve's DEVELOPMENT.md L110). Sources count as changed when the newest source mtime under the git top level is later than the assembly's. A restart builds first, then stops, then launches, so a red build leaves the old game running; it keeps the same session, so error `seq` numbers continue. Step 11 reuses step 12's C# fixture. Settled 2026-09-26 (user, each the recommended option): an import runs when a versioned `*.import`'s `dest_files` target is missing, or `*.uid` files exist with no `.godot/uid_cache.bin`, never merely when `.godot/` is missing (the InputProbe copies run without one, and an import writes `.uid` files beside scripts); a red build refuses `run_project`'s launch with the parsed errors; an import is refused while another session's game runs on the folder. Settled from the explorer's map: `restart_project` relaunches with the stored arguments only (other arguments mean `stop_project` then `run_project`) and refuses an attached session.
    - **Watchdog.** Checked only when a request times out: a 2 s ping, and when that is silent too, the call fails as "main thread is stuck" with the game process's CPU, threads and last stderr lines. The bridge's hello carries the game's own pid (the server's process is the `Godot_console.exe` wrapper). Stop kills at once only when a ping is silent; otherwise it keeps the graceful order.
    - **Baselines.** Stored at `<project>/.godot/godot-mcp/baselines/<name>.png`, written only by an explicit `save_screenshot_baseline`; a compare against a missing one fails with a hint. The comparison runs in the bridge with Godot's `Image` (about 0.1 s at 720p, measured; no new dependency): pixels whose largest channel difference passes a tolerance (default 2/255) are counted, with a bounding box and a changed ratio; a size mismatch fails. The crop is stored with the baseline in a `<name>.json` sidecar and reused by the compare (user, 2026-09-26).
    - **Profiles and batch.** `godot-mcp.json` beside `project.godot`: `{scene, userArgs, engineArgs, resolution, quiet, presets: {name: {…, session}}}`; `run_project`'s `options.preset` merges one, explicit arguments win and user arguments append. Presets launch Godot only, so delve's `dotnet run` server stays outside. The batch tool runs existing tools by name plus assertions (`property`, `expression`, `no_errors`, `wait`) server-side in order, stops at the first failed assertion or tool error, and returns every step's result with screenshots as paths. Settled at build time (user, 2026-09-26): the batch calls tools through the SDK's tool collection; `property` and `expression` assertions check once (a new `wait_for` `timeoutMs: 0`, allowed while paused); `no_errors` looks back to the previous `no_errors` or the batch start; a `screenshot` assertion needs `compare_screenshot`'s `match`; at most 100 steps and 300 s. Profiles: the top level applies to every run, a preset replaces `scene`, `resolution` and `quiet` and appends arguments, explicit arguments win, and parsing is strict.
12. **The headless scene tools** (user, 2026-09-26, each the recommended option of a ranked choice; the rest settled from the explorer's probes). The remaining tools are 14: the reference's ninth node tool is `get_scene_tree`, shipped here as `get_scene_file_tree`.
    - **Values out.** A Node reads out as its path from the scene root (`.` for the root, null outside the scene). A Resource reads out, in the shared `bridge/godot_mcp_json.gd` so runtime `inspect_node` gains it too, as `{resource, uid?, class}` when external and `{class, subResource?, properties}` (its non-default stored properties) when built-in or unsaved. Values in: a Resource-typed property takes `"res://…"`, `"uid://…"`, `{resource}`, `{type, …properties}` or null; a Node-typed export takes a path from the scene root; enums take integers, as runtime `set_property` does.
    - **Edits.** A list edit (`delete_nodes`, `set_node_properties`) is all-or-nothing: one failing entry saves nothing and the result names it. An edit of a node inside an instance is refused, naming the instance's scene (the reference loses it silently: `packed_scene.cpp` L799, L1142). Scenes open with `GEN_EDIT_STATE_MAIN` and instanced children with `GEN_EDIT_STATE_INSTANCE` (the reference's DISABLED flattens inherited scenes and doubles inherited connections: `packed_scene.cpp` L233-236, L682). A save restores the header UID and every `ext_resource`'s `uid=` (a `--script` save writes neither: `resource_saver.cpp` L285-294). A new scene gets a fresh UID (`ResourceUID.create_id`). `duplicate_node` copies by packing the source under a bare holder and instantiating with MAIN (`Node.duplicate()` bakes instances: `node.cpp` L2789-2798); a name collision is refused. A second identical `connect_signal` is refused as already connected; an inherited connection cannot be disconnected.
    - **Imports.** An importable file a request names that has no `.import` sidecar is imported first through prep's import.
    - **Shapes.** `add_node(projectPath, scenePath, nodeType, nodeName, options {parent, properties})`, the reference's top-level position/rotation/scale/visible/modulate moving into `properties`. Write tools always prepare; read tools keep `options.prepare`. `create_scene`'s root is named after the file in PascalCase unless `rootName` is given. Only `.` and relative node paths are taken; `root/…` is refused with a hint. `get_node_properties` returns what `inspect_node` does, and `changedOnly` means the values the scene file stores. `load_sprite` takes any node with a `Texture2D`-typed `texture` property. `export_mesh_library` follows the editor's rule (each `MeshInstance3D` with a mesh under the root, not looking inside one, shapes from `StaticBody3D` children, no previews: `mesh_library_editor_plugin.cpp` L458-618); items and shapes use the node's local transform as the editor does, but the navigation mesh is composed with the item transform, where the editor places it by its region alone and misplaces it under an offset mesh (user, 2026-09-26). `batch_scene_operations` takes every write op and stops at the first failure, saving nothing, as `batch_drive` does. Read-only: `get_node_properties`, `get_node_signals`; destructive: `delete_nodes`, `disconnect_signal`, `export_mesh_library`, `batch_scene_operations`.
13. **Input capture** (user, 2026-09-26, each the recommended option but the last). The bridge records both sources on its one clock, real events from the root Window and injected ones at its dispatch, so a gesture comes back as its raw events and the order between a person's input and an agent's is exact; the alternative, the server logging gestures and merging them with the bridge's real events, put two clocks a round trip apart. A quiet run captures the server's gestures only and says so in a warning, rather than refusing. The bridge streams what it captures to the server in batches, so a capture survives a crash, stop or restart and the next stop returns it; the recommended option, dropping it with the game as snapshots are, would lose the recording of what led to a crash. Orchestrator defaults: the tool is `capture_input` ("recording" already names the Movie Maker video), motions with no button held are dropped unless asked so a drag still replays, and at 2000 events capture stops with `truncated`.
14. **Games listen only to the gamepads players choose** (user, 2026-09-26). None of the user's Godot games treats every connected pad as input. A seat is claimed by a button press on a pad, never by an axis. At connection (and on reconnect, or from settings) each pad's axes are sampled while idle, so a resting value becomes that axis's centre and a pad that jitters at rest is flagged as noisy (the user's idea: this machine's Winwing MCDU rests its stick at -0.98 and jitters). A device `Input.is_joy_known` does not map as a gamepad is listed in settings but never offered at the claim prompt. The rule lives in the shared Godot conventions, and each game builds it from its own plan. This server's gamepad tools inject, when no `device` is given, on the lowest id 0-15 no real pad holds and report it, so an agent claims that pad in a game's selection step as a player would. How (user, 2026-09-26, each the recommended option): the chosen id is kept for the game's life and re-picked only once a real pad has connected on it; the rule is the same in shut-out mode, where real pads are still listed as connected; an explicit `device` a real pad holds is injected as asked with a `warning` naming that pad; `simulate_input`'s raw `joypad_*` events without a `device` follow the same rule. The shared test sessions all launch shut out of real pads, and a test that needs real pads live launches its own game (user, 2026-09-26), rather than a reset that tries to tell which actions a real pad holds.
15. **Scene-file splices, timed captures and stopping timed-out scripts** (user, 2026-09-28, each the recommended option of a ranked choice).
    - **A headless edit keeps what it did not touch** (#24). Godot's saver has no flag that keeps a file's layout (`ResourceSaver.SaverFlags`), so an edit saves as today, then splices: every section the edit left alone keeps its original text byte for byte, and an added or changed node or resource takes Godot 4.7's form, `unique_id=` included. Changed sections are found by comparing sections, ignoring `unique_id` and the saver's id renumbering, rather than by each op reporting what it touched, so an op cannot drop an edit by forgetting to report it. `save_scene` stays a full re-save, the explicit way to bring a file to 4.7's form. A section the splice cannot map falls back to the full save with a `warning`. Ruled out: stripping `unique_id` to match the old sections (the editor's next save adds it anyway), and a splicing `save_scene` (no tool would upgrade a file).
    - **`capture_frames`** (#25). A new tool takes `at` (a list of seconds) or `{every, for}`, counted in game time from the call's start (the sum of scaled frame delta, so it follows timers under `Engine.time_scale`); the bridge grabs in-process with no round trips; a late frame is taken and its lateness reported; at most 1000 frames and 120 s; stamped files in the screenshots folder, `path_only` by default; a paused game is refused as `monitor_property` refuses it. Ruled out: an option on `frame_control` (stepped games only) and a real-time clock (it drifts from the game's timers, the drift #25 reports).
    - **One capture helper, compositing non-embedded windows**, built with `capture_frames` rather than later: every grab (`take_screenshot`, baselines, frame steps, `wait_for`, `preview_scene`, `capture_frames`) goes through one helper that pastes each visible non-embedded `Window` at its offset from the root, the offset checked on a visible desktop. A quiet run launched on the hidden desktop is no longer parked off-screen, since Windows clamps a native popup of a parked root to (0,0) and its offset is lost; attaches and runs off the hidden desktop stay parked (user, 2026-09-28, over landing the helper for visible runs only).
    - **A timed-out `run_script` or `call_method` is stopped** (#26). The server cancels on timeout as it does for `wait_for`; the bridge drops its reference to the script instance, which in 4.7.2 disconnects the suspended coroutine so it never resumes. The bridge restores `Engine.time_scale` and `SceneTree.paused` to their values at the call's start only when it stops a call, and the timeout says what it stopped and restored, and that a coroutine the script awaited on another object keeps running. A script that finishes keeps its changes. Ruled out: a `ctx.cancelled` flag (it changes `execute`'s contract) and a report-only timeout with a `stop_script` tool (the next run is still corrupted when the message is skipped). `run_csharp` keeps its "still running" answer; a snippet stops itself through a token (decision 18).
16. **Moving nodes in a scene file** (#27; user, 2026-09-28). A new `move_node` tool, batchable like every other edit, moves a node among its siblings or to another parent; `add_node` takes the same `options.position`. A position is one object with exactly one of `index`, `before` (a sibling's name) or `after`. A negative `index` counts from the end as Godot's `move_child` does (-1 is last), chosen over refusing negatives. Reparenting is in (chosen over a later item): the subtree keeps its owner, a node cannot move under itself or its own descendant, a name clash under the new parent is refused. A node of an instance or of a base scene is refused, as the editor refuses it, since the saved file cannot record its move (`packed_scene.cpp` L491, L766-776). The splice keeps the saved order of node sections and its self-check compares that order, since a reorder alone changes no section.
17. **No editor bridge** (user, 2026-09-28). `preview_scene` covers seeing a scene an agent edits headless, so no `EditorPlugin` bridge is built. Should the need return, the open questions were enabling a plugin through `override.cfg` rather than the tracked `project.godot` and headless saves racing an open editor's copy of the scene; hybridindie/godot-mcp routes edits through `EditorInterface.get_editor_undo_redo()` and refuses a move while `get_unsaved_scenes()` lists the scene.
18. **A `run_csharp` snippet sees its timeout as a token** (user, 2026-09-28). `SnippetGlobals` gains a protected `CancellationToken Cancellation` that the call's timeout cancels; a snippet passes it to its awaits or checks it in its loops, and one that ignores it keeps running as before. No `Checkpoint()` helper: it would do no more than `Cancellation.ThrowIfCancellationRequested()`. The timeout's reply is unchanged and sent at the timeout; what the snippet does after it (a stop, an exception) is dropped silently, as a reply to a timed-out request id is. Only the helper's `forget` cancels it (the server's cancel, the bridge's backstop and a lost connection all end there), and it reaches the snippet through the bridge's per-frame poll, so a snippet stuck in a main-thread loop that never yields cannot see it; the tool's docs say so. Ruled out: a real-time `CancelAfter` in the helper (it runs on wall time while the server's timeout is load-adjusted, so under load the snippet could cancel first and one call answer two ways), waiting only through helpers that stop on cancel (a snippet's own CPU loop could not be stopped) and a debug-output line on a late stop (noise in the game log).
19. **A C# field named like an engine property does not reach the saved scene** (#32; user, 2026-09-28). Headless, a C# script is a real instance, and `Object::get` asks the script instance before the engine class (`object.cpp` L319-326), so a field such as `private float scale` answers for `Node2D.scale` and `PackedScene::pack` stores it (`packed_scene.cpp` L883, L981-984); the editor writes the file cleanly because it gives a non-tool C# script a placeholder instance. A headless save stores the engine's value for such a name, as the editor does, by rewriting the packed state after `pack`, and its result warns with the field's name; `get_node_properties` and `set_node_properties` read and set engine properties through `ClassDB`, so they agree with the file. Ruled out: refusing the save until the field is renamed (it blocks every headless edit of the scene).
    - **An instanced or inherited node too** (user, 2026-09-28, each the recommended option). Godot builds an instance whole, script included, before it applies the instancing record's overrides with `Object::set`, which the script instance answers first (`packed_scene.cpp` L266, L233, L494; `object.cpp` L239-245), so an override lands on the field. Every instantiation for editing restores the hidden engine values from the SceneState stack, inner scenes first. A non-plain record's pair is dropped when the engine value equals what its instanced or base scenes give the node, found by walking the SceneState stack as the engine's `PropertyUtils` does, never by instantiating the base scene again (that would rerun the user's `_init`). Object values are not restored: a `local_to_scene` resource set raw would be shared by every instance.
20. **Scene-edit frictions from delve-the-dungeon** (#33; user, 2026-09-28, each the recommended option of a ranked choice).
    - **`attach_script` keeps the values the new script still declares**, by the editor's rule (`InspectorDock::store_script_properties` / `apply_script_properties`, `inspector_dock.cpp` L631-683): every storage script property of the old script is stored before `set_script`, and set after it when the new script declares the name and the value's Variant type matches, or an Object value fits the new property's hint. The result lists the kept and dropped names. Ruled out: a stricter same-type-and-hint rule (a swap the editor keeps would lose values here).
    - **A save keeps the source's stored set.** Godot's `pack` compares against the ClassDB default, which is 3 for `layout_mode` on every Control subclass (built parentless) and 0 on `Control`, so a subclass in position mode gains `layout_mode = 0` (`class_db.cpp` L2184-2196, `control.cpp` L978-982, L4911-4912); the editor writes the same line and the loaded scene is identical. Every save with a source drops a pair the source did not store when its value equals what the source node loads as, with a self-check that falls back to the full pack and a `warning`. Ruled out: `save_scene` only, and documenting it as a footgun. The other half (#64): `pack` also leaves out a line the source stored when its value is the default, the class's (`Label`'s constructor sets `SIZE_SHRINK_CENTER`, `label.cpp` L1531) or the instanced scene's, and the splice then took Godot's text for an untouched node. A save that keeps the layout (every edit, a save-as) puts each such pair back when the packed scene still reads that value, with the same self-check and `warning`; an in-place `save_scene` does not, as it brings a file to Godot's form.
    - **`save_scene` save-as splices against the source's text**, so the sections it leaves alone keep their `ext_resource` ids and tag lines; an in-place `save_scene` stays the full re-save of decision 15.
    - **A script with no `.uid` gets one**, computed as the editor's scan does (`ResourceUID.create_id_for_path`, `resource_uid.cpp` L134-154; measured identical to an import's) and written beside it, for scripts and shaders (`should_create_uid_file`, `resource_loader.cpp` L1428-1440); the result names the written file so the agent commits it. Loads outside the editor log "invalid UID" until the cache knows a uid (`resource_format_text.cpp` L491-506), so each uid a headless edit creates is appended to `.godot/uid_cache.bin` when the cache exists (never creating one), and prep imports when the cache's contents lack a scanned `.uid` or scene header uid, which covers an editor save that drops the appended entries (user, #34). Ruled out: importing before every such edit (3-6 s each, and refused while a game runs on the folder), appending without the prep check, and a warning only.
21. **The live tools reach a C# field Godot does not list** (#36; user, 2026-09-28, each the recommended option). The editor binary the server runs lists only a C# script's `[Export]` members, while `get` reads every field (`csharp_script.cpp` L1500-1527, L2725-2750), so `inspect_node`, `set_property`, `wait_for` and `monitor_property` accept a name `in` the node that is not a method, signal or class constant, and `set_property` converts by the held value's type. `inspect_node`'s default listing stays the property list's, documented as `[Export]` members only for C#. Ruled out: listing every C# field by default through the .NET helper (a cold load of about 2 s and a large result on every plain read of a C# node).
22. **A pause and a capture in game time, started from a call** (#41; user, 2026-09-29, each the recommended option). `wait_for` gains `{gameMs: N}` (1-120000; met once N ms of scaled process delta have passed) and `{frames: N}` (1-7200 unpaused process frames), each a condition alone; their clock sums delta on the bridge's `process_frame` as `capture_frames` does, starting at the first frame after the request, and a paused frame adds nothing. Left out, their `timeoutMs` is derived as `capture_frames`' and `step`'s allowances are (N + 10 s; 10 s + 100 ms a frame), up to 600000; an explicit one wins; check-once (`timeoutMs: 0`) and a start while paused are refused. `capture_frames` and the two waits take `options.call {node, method, args}`: the bridge runs it with `callv` in the frame their clock starts and does not await a coroutine, so `at` and `gameMs` count from the method's entry; a refused call, or a new error in the bridge's error feed across the `callv` (a GDScript runtime error or C# exception cannot be caught), answers that error and no frames. `batch_drive`'s wait assertion takes the new conditions but no `call`: a `call_method` step goes before it. Ruled out: keeping the 10 s default (a long game-time wait reads `met: false` as the effect not happening), keeping the frames and listing the error (frames of a broken effect read as the real one), and awaiting a coroutine before the clock starts (a method that awaits its whole effect starts the clock after it ended, the miss #41 reports).
23. **Joining a game that is already running** (#48; user, 2026-09-29, each the recommended option). The bridge is an autoload that `override.cfg` names, read only when a game starts (decision 2), so a game started with no override has no bridge and nothing can join it. What can be joined is a game started while the override was there, so a folder is **armed** ahead of time.
    - **`arm_project` and `disarm_project` tools** arm a folder: the override and `armed.json` stay until the disarm or the server's exit. Ruled out: an option on `attach_project` that keeps the override after its wait (arming as a side effect of a call that may have timed out), a `godot-mcp.json` setting (the override present whenever the server runs, wanted or not), and a clearer refusal only.
    - **A game started on an armed folder is dormant**: its bridge dials nothing and registers no logger. It writes `dormant/<pid>.json` and checks twice a second for its own `join-<pid>.json`. So the error feed starts at the join. Ruled out: buffering errors from start (a logger in every armed game, joined or not).
    - **Which game:** `attach_project` joins the one dormant game when there is one, takes `options.pid` to choose among several, and refuses with the list when several wait and no pid is given. `list_sessions` lists the dormant games under `armed`. Ruled out: the first bridge to see a shared file (delve's server and clients share a folder, so the agent could not choose), and refusing whenever more than one waits.
    - **Arguments:** `attach_project` became `(projectPath, waitSeconds, options {quiet, shutOutRealGamepads, session, pid})`, `run_project`'s shape, since the five-parameter limit left no room for `pid`. The old top-level arguments were removed. Ruled out: moving only `session`, and a separate `join_project` tool.
    - **After a detach**, a joined game on a still-armed folder goes dormant again and can be joined again; a window a quiet join parked comes back on screen. Ruled out: leaving it idle for good.
24. **Servers and joins sharing a folder** (user, 2026-09-29, each the recommended option).
    - **Across servers, a write whose settings differ from a live other owner's is refused**, as decision 10 refuses it inside one server: an `override.cfg` whose `quiet`, `shutOutRealGamepads` or bridge path differ, and an `armed.json` whose `quiet`, `shutOutRealGamepads` or `mute` differ, naming the other server's pid, its values and how to match them. The files already carry the settings and the owners. Ruled out: a warning with the last writer winning (the first server's game changes under it, and only the second agent is told), and leaving it as is.
    - **Joins of different dormant games wait at once**: a join may wait beside a join of another pid or beside a plain attach; a second join of the same pid is refused naming the waiting session, a second plain attach stays refused as before, and a join's cleanup deletes only the join file carrying its own token. This amends decision 10's "an attach is refused while another attach on the same folder is still waiting", which predates joins. Landed on `main`, not a feature branch. Ruled out: keeping the refusal (a multi-client drive joins its games one after another).
25. **Input targets: world nodes, shown text and list items** (each the recommended option; the design and its engine facts are in [plans/input-targets.md](./plans/input-targets.md)).
    - **`element` takes any `CanvasItem` or `Node3D`**: a node that is not a Control is a world aim, and `aimedAt.kind` says which it was. Ruled out: a separate `node` key (two keys for "a node", and a Sprite2D passed as `element` costs a refusal and a second call).
    - **A world node is aimed at its origin plus `offset`** in local units, and the point is reported. Ruled out: the visual centre (an `Area3D` whose shape sits off its mesh is missed, and the point is hard to predict from the scene file) and the origin with no `offset` (half-off-screen cards need `{x, y}` again).
    - **A text target matches the exact shown text**, trimmed and case-sensitive; a miss lists up to five near misses and every node named like the text with what it shows. `get_ui_elements`' `text` is the same shown text. Ruled out: a substring fallback ("Play" pressing "Play Again" on the wrong screen) and a name fallback.
    - **Several matches are refused**, listing up to 10 with their paths (items: index) and rects, narrowed with `under`, `path` or `index`. Ruled out: an `nth` key and the first match (tree order is not screen order; delve's hand reorders its children).
    - **A match that takes no clicks** (a card's title Label) is aimed at, and a hit in the same scene instance (the same non-null `owner`) is accepted and named in `pressedOn`. Ruled out: skipping the hit check (a modal takes the click and the call reports success) and matching only click-taking Controls (cards stay unreachable by title).
    - **An item not reachable now is refused with the fix and the numbers**, except a closed `OptionButton`/`MenuButton` popup, which the gesture opens with a real click on the button first (`aimedAt.opened`). Ruled out: refusing the closed popup too (every option pick takes two calls) and reaching items by setting state (`scroll_to_item`, `show_popup`), which skips the input a player makes.
    - **A `PopupMenu` item's point is found by probing with real motions**, reading `get_focused_item()` after each and bisecting on y, since `PopupMenu` binds no item rect or hit test. The probe's motions carry a velocity, since a `PopupMenu` ignores a zero-velocity motion. A disabled popup item is refused (`get_focused_item()` reads -1 over it, so the aim cannot be confirmed); a popup whose search filters its items is refused in place of a hidden-item refusal (it binds no read of which items the search hides); an item in a submenu takes two calls, the first opening the submenu (`aimedAt.item.submenu`), the second naming the submenu `PopupMenu` as `element`; `hover` on an item of a closed popup is refused and never presses; a native popup is refused. Ruled out: recomputing the layout from theme constants (a theme or engine change moves the click silently) and the keyboard (`set_focused_item` then `ui_accept` never plays the mouse path).
    - **A SubViewport shown without a `SubViewportContainer` is refused**, naming it: only a container forwards input, so a press there would not reach it. Ruled out: mapping through a `TextureRect` showing its texture (mapping code for one scene, and other ways of drawing it still fall to the refusal).
    - **Popup tests run on a shared session with the real pads live**, since shut-out mode's re-sent focus-out closes a Popup as it opens (decision 14).
26. **Game tools** (each the recommended option; the design is archived in [plans/archive/project-tools.md](./plans/archive/project-tools.md)).
    - **A game marks a tool with its own attribute class**, matched by the name `GodotMcpToolAttribute` in any namespace and read through `CustomAttributeData`, with parameter descriptions from the BCL's `[Description]`; the game takes no package. Ruled out: a NuGet annotations package (a tracked build change and a runtime dependency for a dev-only feature, and version skew with the installed server), a method-name prefix (no description or `When`), a manifest in `godot-mcp.json` (drifts from the code) and every public method of an autoload (plumbing such as delve's `Send` offered beside the cheats).
    - **A tool's owner is an autoload, the current scene's root or a static**; a marked method anywhere else is listed `available: false` with the reason. Ruled out: any node in the tree (several instances make a tool ambiguous, and every list walks the tree) and autoloads and statics only (a scratch root's `PlayStep` could not be a tool).
    - **Two fixed tools, `list_game_tools` and `call_game_tool`**, the game's tools being data. Ruled out: one dynamic MCP tool per game tool, since an agent spawned with a `tools:` line never sees a tool added after the install's sweep, and whether a client re-lists on `list_changed` is unverified.
    - **The list is read from the live game through the helper**, kept per game process, so it never offers a tool the running build lacks; a stale build is reported (`build: "stale"`), never refused. Ruled out: reading the built assembly's metadata in the server (lists the disk's build and needs a second reader) and reading at every C# launch (every launch pays the helper's load).
    - **Arguments are an object keyed by parameter name**, checked against the schema before the game is asked. Ruled out: a positional array (argument meanings read off the schema by position).
    - **A call answers the method's return value**, a `Task` awaited; games are told that a tool meant for agents returns what happened. Ruled out: a settle window after each call (slower, and a game's refusal notices are not errors) and a companion "why refused" method (a second convention most tools lack).
    - **C# only**: a GDScript project is refused, naming `call_method`.
27. **State digest** (each the recommended option but the last; the design and the spike are in [plans/state-digest.md](./plans/state-digest.md)).
    - **A node opts in by joining the `mcp_state` group** and defining `_mcp_state()` (GDScript) or `_McpState()` (C#: any accessibility, no parameters, any return type, found by reflection in the helper and written by `ValueWriter`). Ruled out: an attribute on fields and members (marks scattered over many classes and a second attribute file) and a Godot-visible `_McpState` returning a Godot Dictionary (no records, the state delve would return), and finding nodes by the method alone (every read walks the tree and loads the helper even when nothing is marked).
    - **Godot sees a C# method by its signature, not its accessibility**: a `public`, `internal` or `private` method whose return and parameters marshal to Variant passes `has_method` and `call`, and one returning a record passes neither (measured on 4.7.2; `ScriptMethodsGenerator.cs` L128-135, `ExtensionMethods.cs` L302-334). The game repos' notes that only a public method is seen do not hold for a method Godot can marshal.
    - **No fallback**: a group member without a state method reads as an `error` entry, and a game with no marked node gets an empty list and a hint naming `snapshot_subtree` and `get_ui_elements`. Ruled out: falling back to script variables and `[Export]` members (layout knobs, not state) and a visibility tier (it duplicates `get_ui_elements` and `snapshot_subtree`).
    - **A new tool, `get_game_state`**. Ruled out: an option on `snapshot_subtree` (seeing the state takes a snapshot and a diff) or on `inspect_node` (one node a call, and a read-only tool running game code).
    - **`keep` stores the read in the session's snapshot store**, flattened to one value per leaf keyed by its dotted path, so `diff_snapshots` reports a changed hit point as one entry. Ruled out: comparing top-level keys whole, and no diffing (two full results in context).
    - **`get_game_state` and `diff_snapshots` are destructive with a `read` class override**, since state methods are game code and a live re-read runs them. Ruled out: `ReadOnly` (a client that auto-approves reads runs game code unasked) and no override (the read-only agents never get the tool).
    - **One frame**: the bridge's `state` handler reads the GDScript nodes and calls the helper inline for the C# ones. Ruled out: two requests merged by the server (halves read frames apart, so a kept read diffs noise) and the helper reading every node (two walks and two value writers kept alike).
    - **Waiting on a state key is in the first version**: a `wait_for {node, state, equals}` condition and the matching `batch_drive` assertion, chosen over leaving C# games to poll with repeated reads.
28. **Warm headless hosts and the scratch runner** (each the recommended option; the design and its spike are archived in [plans/archive/warm-headless.md](./plans/archive/warm-headless.md)).
    - **A host restarts on any change under its project it did not make**: the fingerprint is compared before each request and retaken after each reply, and after each reply the host checks that no `res://` path the request named is still cached (scripts skipped, since the GDScript cache keeps them by design). Correctness rests on stat calls, not on how Godot's caches behave. Ruled out: restarting only for what a process cannot reload (a resource still held is read stale, and an edit saves over an outside change) and a `FileSystemWatcher` (its handle blocks a delete or rename of the folder, and an overflow drops events silently).
    - **An idle host stops after 5 minutes of wall time**, at most 4 run at once (a fifth folder stops the least recently used idle one, never a busy one), and an idle host runs at `Engine.max_fps` 30, lifted for a request. Ruled out: living until the server exits (hosts pile up across worktrees) and 30 seconds (most pauses between an agent's calls are longer).
    - **A failed request fails its call**, quoting the log from its own request's marker; the host is dropped and nothing is retried. Ruled out: retrying reads (two paths per op) and retrying every op (an edit that saved and then crashed is applied twice).
    - **C# projects keep one process per call**: a warm C# host logged spurious `Handle is not initialized` engine errors in a soak that no cold run shows, so warm hosts serve GDScript-only projects until a follow-up spike finds the cause.
    - **`stop_project` stops a folder's host**, since `--path` makes the project the host's working directory and holds the folder against a rename or delete: `projectPath` stops that folder's host and its session, stopping a session also stops its folder's host, and the result carries `headlessHostStopped`.
    - **The server walks a scratch scene's steps** in a headless game session, `call_method PlayStep` then a `wait_for {gameMs}` of its pace per step, with the scene's own clock off. Ruled out: the scene's `--scratch-auto` with the server parsing the log (verdicts by text search, per each game's log format) and both together (step bounds from log lines, errors from the feed, two clocks a frame apart).
    - **Pace, known reasons and patterns live in a strict `scratch` section of `godot-mcp.json`**. Ruled out: arguments on each call (every agent must know every scene's pace) and a `GetPace()` on the scene (a game change for a runner setting).
    - **A step is also red on an output line in its window matching `scratch.patterns`**, by default Godot's own error lines and the leak line. Ruled out: the error feed and exit code only (a `GD.PrintErr` failure from a timer passes) and porting each game's text rule (the games disagree on case and skips).
    - **A fresh headless game per scene.** Ruled out: one game per folder reused with `change_scene_to_file` (autoloads, statics and the command line stay the first scene's, and leaks are one total).
29. **Timeline watch** (each the recommended option; the design and the spike are in [plans/timeline-watch.md](./plans/timeline-watch.md)).
    - **One `watch` tool with `start`, `stop` and `run`**, one watch per session, `stop` taking no id; `run` replaces `monitor_property`, which is removed once `run` lands. Ruled out: a blocking call only (nothing can drive the game during the window, delve's case), separate start and stop tools beside `monitor_property`, and keeping `monitor_property` or a forwarding form (two tools for one job).
    - **Every other tool runs beside a watch**, `frame_control`'s steps included; only a second watch is refused. Ruled out: `monitor_property`'s guard (a stepped sequence could not be watched).
    - **Tracks are properties, expressions, signals and monitors.** Signals are connected on a node or on a group's members at start, not followed as nodes join. C# members Godot's `get` cannot read are not watched in the first version (a record reads null with a hint naming `cs_get` and the state digest). Ruled out: properties and signals only (a focus owner or a child list still needs a sampling script), state keys read through state methods every frame, following `node_added`, and per-frame helper reads (they move the frame time being measured).
    - **The window is `frames` or `gameMs` over unpaused frames**; paused frames are skipped and listed. Ruled out: wall time (it drifts from the game's timers) and frames only.
    - **Samples are taken at `process_frame`**, signals stamped with the frame they fired in, a one-frame offset the docs explain. Ruled out: `frame_post_draw` (no samples while the window cannot draw).
    - **The result is per-track change points plus one merged event list**, a busy track keeping its first 200 and last 50 change points with `dropped` and a `minDelta`, its summary covering every sample; the bridge applies the point and event caps as it records, since an unbounded series held the game's main thread about 200 ms in the spike. Ruled out: one merged timeline (a tween buries the emissions), summaries only, decimation (a one-frame event disappears) and failing on overflow (an unrepeatable moment is lost).
    - **Monitors are a track kind of the same watch**, so a hitch shares frame numbers with its cause; `frame_ms` is the wall time between `process_frame`s, and `time/fps`, `time/process` and `time/physics_process` are refused, since the engine sets them once a second. Ruled out: a separate monitor tool, per-viewport render times (the watch would change a rendering setting) and the `time/*` monitors as they are.
    - **`watch` is destructive with a `read` class override**, since expressions, custom monitors and `options.call` run game code.
    - **Settled for its first landing**: a track kind and its result key arrive with the step that implements them; a `stop` with no watch is refused; `start` with `options.call` answers after the first frame, carrying the call's value or failure; a start on a paused game is accepted; the bridge holds a started watch's deadline (`deadlineMs`); a detach drops a running watch; a track is keyed by its `name`, else its node and property, and two tracks on one key are refused; `minDelta` applies to numbers and vectors only; a watch outlives the `batch_drive` that started it.
30. **A patched Godot only when stock cannot meet a need.** Each need is solved on stock 4.7.2 first; a need stock cannot meet gets a small patch sent upstream as a PR and carried only until it merges; a patches repository and a rebuild pipeline come only if upstream will not take a patch. No need qualifies today.

## Wire

- **The server listens and the bridge dials in.** The server binds `127.0.0.1:0` and keeps the listener open, then passes the port and a session token to Godot through environment variables (`GODOT_MCP_PORT`, `GODOT_MCP_TOKEN`). This removes the reference server's free-port race and its regex-editing of the port into GDScript.
- **Frames** are a 4-byte length plus UTF-8 JSON.
- **Every request carries an id** and every reply echoes it. A reply for a timed-out id is dropped, not matched to the next request.
- **Handshake:** the bridge's hello carries the token and the project path; a mismatch is refused, which catches a stale bridge.

## Coexisting with a debugger (user, 2026-09-26 and 2026-09-27)

An agent debugs a game godot-mcp holds with DebugMCP and netcoredbg; the two servers stay separate, and godot-mcp wraps no debugger.

- `list_sessions` keeps `processId` (the wrapper `stop_project` kills) and adds `gameProcessId`, the hello's pid, the one a debugger attaches to.
- While a debugger is attached to the game (`CheckRemoteDebuggerPresent`), each runtime call pings first for 500 ms and fails at once when the game does not answer: it is most likely paused at a breakpoint. A game with no debugger attached is untouched.
- `stop_project` and `restart_project` go ahead while a debugger is attached, and warn that its debug session ended with the game.
- No hold-until-attached launch option (decided 2026-09-27, after the trial recorded in the `debug-live` skill): a run stops Godot at its 15 s handshake timeout, and netcoredbg cannot attach before the runtime starts. Startup code is debugged by launching Godot under netcoredbg while `attach_project` waits; the listener holds a hello read open for as long as any session waits for a bridge, since the bridge dials in `_ready`, says hello in its first `_process` and never redials.

## Gamepad input, from Godot 4.7.2's source

- **What works.** A parsed `InputEventJoypadButton` updates `is_joy_button_pressed` (`input.cpp:977-987`). A parsed `InputEventJoypadMotion` updates `get_joy_axis`, raw with no deadzone (`input.cpp:989-993`, `601-614`). Actions match through `InputMap::event_get_index`: pressed means `|value| >= deadzone` (default 0.2, `input_map.h:55`), and strength is `inverse_lerp(deadzone, 1, |v|)` (`input_event.cpp:1133-1171`). Joypad events are never merged by accumulated input, and `is_echo()` is always false.
- **Focus navigation.** The default `ui_left/right/up/down` have d-pad buttons plus the left stick at ±1.0 (`input_map.cpp:490-512`) and all devices (-1), so they react to injected events. A stick push moves focus only on the released-to-pressed change, so the next move needs a 0.0 release first (`viewport.cpp:2340-2380`, `input.cpp:1033-1034`). `ui_accept`, `ui_cancel` and `ui_focus_next` have no joypad binding by default; `ui_select` is Y.
- **Devices.** The first pad is device 0; ids 0-15 are joypads (`input_event.h:64-67`).
- **Not settable from script.** `get_connected_joypads`, `is_joy_known`, `get_joy_name`/guid/info and vibration are script-callable but filled only by the platform driver's `joy_connection_changed`, and only its signal is bound (`input.cpp:153`, `239`, `711`, `747`, `2291-2301`). An injected pad never shows as connected; the real pads do, in shut-out mode too, which is how the pad tools find a free id. Neither project calls those queries (checked 2026-09-25). A game that does would need an OS-level virtual pad.
- **Losing focus can clear pad state.** The setting is `input_devices/joypads/ignore_joypad_on_unfocused_application`, default false (`ProjectSettings.xml` L1671; defined at `input.cpp` L2374).
  - Pad state is cleared only in a project that sets it true, on `NOTIFICATION_APPLICATION_FOCUS_OUT` (`scene_tree.cpp` L934-942, `input.cpp` L1600-1623).
  - While it is true and the application is unfocused, the driver's real pad input is ignored (`input.cpp` L1652, L1684), but events injected through `parse_input_event` still get through.
  - Enum values were checked against `input_enums.h` L68-102.
- **Shutting real pads out is opt-in** (user, 2026-09-25). This machine has four pads connected, and in the gamepad tests they moved menu focus and pushed an action's strength mid-test.
  - The only script-reachable shut-out is to set the setting true and mark the game unfocused: pad state updates in `Input` before any script sees the event. A real focus-in turns the pads back on (`scene_tree.cpp` L934-942), so the bridge re-sends a focus-out after every focus change and restores held injected pad state.
  - The costs: the game sees application focus-out notifications, and delve mutes on them (`Main.cs:340-352`, when its mute-in-background option is on). Held injected keys release on a real focus change, and held pad buttons fire "just pressed" again. Every `Popup` closes as it opens, since a popup hides itself on the application focus-out (`popup.cpp` L114-120 in 4.7.2; found 2026-09-26, when the shared test session went shut out and its popup test launched a run of its own with real pads live).
  - So the default leaves real pads live (the setting written false). `shutOutRealGamepads: true` on `run_project`/`attach_project` turns the shut-out on, and the gamepad tests use it.
  - This reverses a same-day first decision of "shut out by default", made before these costs were measured.
- **Releases are sent explicitly** (`pressed=false`, or `axis_value=0.0`), and every event is a new object.

## The error feed, from Godot 4.7.2's source

- `Logger` extends `RefCounted` with `_log_error(function, file, line, code, rationale, editor_notify, error_type, script_backtraces)` and `_log_message(message, error)` (`core/core_bind.h` L125-138); `ErrorType` is ERROR 0, WARNING 1, SCRIPT 2, SHADER 3. `OS.add_logger` catches only what is logged after it; the logging tutorial registers in an autoload's `_init()`. Script loggers are removed at shutdown (`core/object/script_language.cpp` L335-339); the list has no lock, so `remove_logger` while threads log is unsafe and the bridge never calls it.
- `_log_error` runs on the thread that raised the error with no engine lock (`core/error/error_macros.cpp` L125-133, `core/os/os.cpp` L98-151); a per-thread guard sends an error raised inside it to stderr only (`error_macros.cpp` L49, L116-121). So it only appends under a `Mutex`, and the main thread sends.
- Engine `_MSG` errors put the condition in `code` and the message in `rationale`; `push_error`, `push_warning` and GDScript runtime errors put the text in `code` (`core/error/error_macros.h` L426-428, `core/io/logger.cpp` L67-72). `push_error`'s function/file/line are its C++ site (`core/variant/variant_utility.cpp` L1023, L1033; Godot issue #119628), so the script's location is backtrace frame 0.
- GDScript runtime errors reach loggers in debug builds only (`modules/gdscript/gdscript_vm.cpp` L3963-3993); backtraces are filled in debug and editor builds or with `debug/settings/gdscript/always_track_call_stacks` (default false, `gdscript.cpp` L2871-2875). Runtime `load()` parse errors arrive as `function="GDScript::reload"` (`gdscript.cpp` L824-853). Nothing arrives with `application/run/disable_stderr` on, or outside startup-to-shutdown (`main.cpp` L2363-2376, PR #117790). Loggers are additive: the console logger stays (`os.cpp` L829-835).
