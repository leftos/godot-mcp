# Using the godot-mcp tools

For an agent driving a Godot project through this server: which tool fits a job, what each one does, and the edges that bite. Words such as session, quiet run, prep, baseline and headless run are defined in the [glossary](./README.md#glossary). Each tool's wire-level result shape and bridge command are in the tool table of [ARCHITECTURE.md](./ARCHITECTURE.md#tools); the tool's own schema in your client has every argument.

## Which tool for which job

| Job | Reach for | Instead of |
|---|---|---|
| Start the game and drive it | `run_project`, then the runtime tools | `attach_project`, which is for a game started some other way |
| Drive a game you (or the editor) started | `attach_project` | `run_project` |
| Look at a game a launcher or a player already has running | `arm_project` before it starts, then `attach_project` at any time | a delayed launcher timed against `attach_project` |
| See one scene without playing | `preview_scene` | `run_project` with `scene` plus `take_screenshot` plus `stop_project` |
| Play a project's scratch scenes step by step and get a verdict each | `run_scratches` | a `Run-Scratches.ps1` script parsing a `--scratch-auto` log |
| Pick a thing to click | `get_ui_elements` (Controls, with viewport rects) | guessing coordinates from a screenshot |
| Click, drag, type | `click`, `drag`, `type_text`, `key` | `simulate_input`, which is for event sequences the gestures cannot make |
| Pick an option from a dropdown or a menu (`OptionButton`, `MenuButton`, `PopupMenu`) | `click` with `{element: <the button>, item: {text}}`, which opens the popup first | setting `selected` and emitting `item_selected` by hand; clicking the button, then coordinates read off a screenshot |
| Hover a Control, see its tooltip | `hover` (waits for the tooltip, returns its text and rect) | a `mouse_button` release as a hover, a `wait_for` as a sleep |
| Scroll a list or container, wheel-zoom | `scroll` (wheel notches or a trackpad pan) | a `run_script` that parses wheel events |
| Drive with a pad | `gamepad_button`, `gamepad_stick`, `gamepad_axis` | `simulate_input` joypad events |
| Land a check on an exact frame | `frame_control` (`pause`, `step`), then `wait_for` with `timeoutMs: 0` | `wait_for` with a timeout on a running game |
| Watch a value change over frames | `watch {action: "run"}` with a property or expression track | a loop of `inspect_node` calls |
| See what several values did while you drive (a dialog leaving, the focus moving, a counter stepping) | `watch` `start`, then any tools, then `stop` | a sampling `run_script`, which keeps every other call from reaching the game while it runs |
| Find the frame that hitched, and what the game was doing then | `watch` with `tracks.monitors: ["frame_ms"]` beside the signals or values of the moment | a `run_script` timing `process_frame` gaps by hand; Godot's `time/process`, which holds the last second's longest frame |
| Frames at set moments of an animation or a timed sequence | `capture_frames` | a `take_screenshot` per moment, whose timing drifts |
| Press an InputMap action | `simulate_action` | `key` on a key bound to it |
| Find the input a game cannot survive | `stress_input` | a hand-written loop of random `simulate_input` calls |
| Wait for something to happen | `wait_for` | polling `inspect_node` or `run_script` |
| Read or change a live node | `inspect_node`, `set_property`, `call_method` | `run_script`, which is for anything those three cannot say |
| Read a game's own state (turn, hit points, the cell a player stands on) | `get_game_state`, when the game marks nodes | a screenshot, or a sampling `run_script` |
| See everything an action changed in a subtree | `snapshot_subtree`, act, `diff_snapshots` | `inspect_node` on each node before and after |
| Learn a class's members | `describe_class` | guessing names, then reading `call_method` errors |
| Learn a C# object's or type's members, private ones and overloads included | `cs_members` | `describe_class`, which shows only what Godot's call can reach |
| Read or change a C# member Godot's `get`/`set` cannot reach (a private record field, a `List<T>`, a static) | `cs_get`, `cs_set` | `inspect_node`/`set_property`, which read such a member as null (a private field of a Godot type, such as a `float`, they do reach by name) |
| Run several C# steps in the game at once: build a record and pass it, loop, await | `run_csharp` | a chain of `cs_call`s, or `run_script`, which cannot name C# types |
| Find and call a game's own cheats and debug commands | `list_game_tools`, then `call_game_tool` | reading the game's source for its cheat methods, then `cs_call` with positional arguments |
| Call a C# method Godot's call cannot reach (overloads, generics, records, statics, an async `Task`) or construct a C# object | `cs_call` | `call_method`, which marshals only Variant types |
| Find a live node | `get_scene_tree` | `get_scene_file_tree`, which reads a scene file |
| Know what went wrong | the `errors` in each result, then `get_errors`, then `get_debug_output` | reading stdout first |
| Replay a known sequence with checks | `batch_drive` | one tool call a step |
| Turn what a person (or a drive) did into a replayable sequence | `capture_input` start, play, stop, then `simulate_input` with its `events` | writing the events by hand from a description |
| Catch a visual regression | `save_screenshot_baseline` once, `compare_screenshot` or a `screenshot` assertion after | comparing screenshots by eye |
| Keep a video of a bug | `run_project` with `options.record`, `record_mark`, `stop_project` | an OS screen recorder |
| Check scripts and scenes load | `validate` | launching the game to see if it errors |
| Edit a scene file | the headless scene tools, several edits at once through `batch_scene_operations` | writing `.tscn` text by hand |
| Set a project's launch defaults | a `godot-mcp.json` beside `project.godot` | repeating `engineArgs` on every `run_project` |

## Rules every tool shares

- **Arguments are checked by name.** An argument or options key a tool does not take is refused (`run_project has no argument 'optoins'; it takes: …`, `options has no 'prepar'; it takes: …`), as is a value of the wrong kind (`options.prepare takes a string, not true.`, followed by that option's description) and a missing required one (`run_project needs the argument 'projectPath'.`). Free-form values (`add_node`'s `options.properties`, `set_node_properties`' `value`) take any keys. `batch_drive` and `batch_scene_operations` steps are checked the same way, behind their step prefix.
- **Session.** Every runtime tool, and `restart_project`, `stop_project`, `detach_project` and `get_debug_output`, takes a last `session` argument. Pass the session `run_project` or `attach_project` returned on every call from the start: another agent's game can start on the same server at any time, and there is no default session. It may be left out while only one session exists; with several live ones and no name the call is refused and lists the live ones, with a count of the stopped. A name no session has is refused the same way. A new session is named after its project folder, fitted to the name rule (1 to 64 letters, digits, `.`, `_`, `-`; any other character becomes `_`, so `My Game` becomes `My_Game`). When a live session on another folder already holds that name (two worktrees of one repo), the new one takes `<name>-2`, `-3`, …, cut to fit 64 characters; read it from the result's `session`. Two sessions on one folder need distinct names: pass `options.session` to `run_project` or `attach_project`. The headless tools and `preview_scene` take `projectPath` instead and no session.
- **Errors ride along.** A runtime tool's result carries `errors` (file, line, stack) for every error the game raised while the call ran, and the call still succeeds, except `run_script` and `call_method` as their sections say. The key is present only when the game raised an error during the call: its absence means none. Read `errors` in every result before the next step.
- **Viewport coordinates.** Every `x`, `y` an input tool takes is in viewport coordinates, as `get_ui_elements` reports rects; the bridge maps them to the window whether it is stretched or letterboxed. A screenshot's pixels are the window's, which differ from the viewport's when the project stretches (a 640x360 viewport in a 1000x900 letterboxed window captures 1000x562), so a point read off a screenshot is not a viewport point; a `crop` is in viewport coordinates, so a rect `get_ui_elements` or `hover` reports crops as it is, at the window's scale. Aim at `{element}` where a Control or a world node exists.
- **Paging.** Long lists come back one page at a time with `total`, `offset` and, while more remain, `next`: pass `next` as the next call's `offset`. A value longer than its budget comes back as `{valuePreview, valueLength}`.
- **Quiet by default.** `run_project` starts the game quiet: unfocused, off-screen, click-through, silent, with no real input reaching it, and capped at 60 fps unless the project sets its own `application/run/max_fps` (a recording run keeps its fixed 60). Pass `options.quiet: false` only when the user wants to watch or play along, with `options.mute: true` when they want to watch without sound. Sessions on one folder must agree on quiet and on `shutOutRealGamepads`, across godot-mcp servers too; a new session that differs is refused, naming the other server's pid when it is another server's, and so is one whose install injects another bridge.
- **Headless tools and live sessions.** Every headless tool (`validate`, `get_scene_file_tree` and the scene tools) runs beside a live session on the project folder, of this server or another: the game keeps running and keeps its `override.cfg`, and the headless run's bridge stays off. A running game reads a scene only when it loads it, so see a headless edit with `restart_project` or `preview_scene`. `preview_scene` is not headless and runs beside a live session too.
- **Paths.** Headless and preview paths are `res://` paths or paths relative to the project folder, inside it, and must match the case of the file on disk; a case variant is refused with the right spelling. A node path in a scene file is relative to the scene's root (`.` for the root, `Boss/Sprite`), never `/root/...`. A live node (runtime tools) is an absolute path (`/root/Main/Button`), a path under the root (`Main/Button`) or a bare name found breadth first, or a unique name: `%Rows` alone is looked up in every scene under `/root` (several scenes holding it is refused, naming their owners), `%Rows/Label` reads on from it, and `Glossary/%Rows` after its owner's path; the same rule in the GDScript tools, the `cs_*` tools' `{node}` and `run_csharp`'s `Node(path)`. A path that names no node is refused with the base it was read from, the deepest node on it that exists, the name that node lacks and up to 10 of its children (`(+n)` for the rest): `No node 'Main/Missing' in the running game: a path is read from /root, and /root/Main has no child 'Missing' (children: HUD, Board); …`; a bare name says none was found anywhere under `/root`. Every tool that names a node refuses this way, the input tools' `{element}`, `wait_for`'s signal wait, `watch`'s tracks and a `{"$node": path}` argument to the C# tools included; the closing hint points to `get_ui_elements` for an input target and to `get_scene_tree` elsewhere.
- **C# projects.** A launch, a restart and every headless tool run the prep first: a stale C# assembly is built and missing or outdated imports are run (an asset whose source bytes changed since its import, read from Godot's `.godot/imported/*.md5` only when the source is newer, or whose `.import` settings changed since the server last saw them, recorded in `.godot/godot-mcp/import-fingerprints.json`; a settings change made before the server first prepped the folder needs the editor opened once); the result's `prep` says what was done, and `buildLog` / `importLog` name the full log of a build or import that ran (the next one overwrites it). An import that is due while another session's game runs on the folder is refused, not run under the live game: stop those sessions, or pass `options.prepare: "never"` to go on without it. A failed build refuses a launch with its compiler errors, naming the configuration built (`The Debug C# build of …`). The headless write tools will not save a scene that uses C# scripts while the build fails (nor `attach_script` a `.cs`, nor `connect_signal` to a C# method), and the refusal quotes up to 20 compiler errors, then `(and N more)`; its "Godot logged:" section leaves out the lines the missing assembly causes, counting them as `(and N lines a missing C# assembly causes, left out: the build failed)`. While the build fails, every headless scene tool's result carries `csharp: {build: "failed", errors, errorsOmitted?}`, and `errors` leaves out the lines a missing project assembly causes (a C# autoload that "does not inherit from 'Node'", a C# script whose class could not be found): `csharp` is their cause. A GDScript autoload's failure still reports. `options.prepare: "never"` skips the prep on the tools that take it.
- **Scene edits keep the file's own text.** The in-place scene tools (`add_node`, `delete_nodes`, `duplicate_node`, `move_node`, `attach_script`, `load_sprite`, `set_node_properties`, `connect_signal`, `disconnect_signal`, `batch_scene_operations`) rewrite only the sections they add, change or delete; every other line of the `.tscn` stays as it was, so the diff shows the edit. An edited node's header keeps its `unique_id` as it was (none in a scene that has none); only an added node gets one. When that cannot be done, the file is saved in Godot's full 4.7 form and the result carries a `warning` saying why. An in-place `save_scene` writes the full form: use it to bring a file to 4.7's form on purpose; a `save_scene` save-as splices against the source like an edit. No save adds a property line the source did not store for a node when the node loads the same without it (Godot's own pack writes `layout_mode = 0` on a Control subclass in position mode); when leaving such a line out would change the loaded scene, the save keeps every line and its `warning` says which property. The other way round, an edit or a save-as keeps a line the source stored that Godot's pack leaves out as a default (a `Label`'s `size_flags_vertical = 4`, an instance's anchors equal to its scene's) while the node still reads that value; an in-place `save_scene` drops it.
- **A script with no `.uid` gets one.** When a scene tool writes a reference to a `.gd`, `.cs`, `.gdshader` or `.gdshaderinc` file that has no `.uid` beside it, it writes the one the editor's scan would (the same id), and the result's `uidFilesWritten` lists the `.uid` files: commit them with the scene. Each uid a scene tool creates (a `.uid` file's, a new scene's own) is also added to `.godot/uid_cache.bin` when the project has one, so a Godot run started outside the server knows it; if an editor open on the project drops it again, the next `run_project` imports.
- **A C# field named like an engine property does not reach the file.** Headless, a C# script runs as a real instance, so a field such as `private float scale` on a `Node2D` answers for `Node2D.scale`. Every headless save (the in-place tools, `create_scene`, `save_scene`) stores the engine's value instead, as the editor does, and the result's `warning` names each field (`MoteTrail.scale (a C# field) hides Node2D.scale; the file stores the engine's value`); `get_node_properties` and `set_node_properties` read and set the engine property. This holds for an instanced or inherited node too: its scene's override (`scale = Vector2(2, 2)` on an instance) is kept, read and duplicated, and a save adds no line the instanced scene already supplies. In the running game the field still hides it: renaming the field is the fix.
- **Timeouts are load-adjusted.** Every timeout and ceiling below, the ones you pass (`timeoutMs`, `waitSeconds`) included, counts load-adjusted time: wall time on an idle machine, slower while other work (a build, a test run, another game) loads it, so a busy machine stretches a wait instead of failing it. Each one also ends at 5 x its value in wall time, and its error then adds `; that is 5 x its <n> s ceiling in wall time, the backstop (load-adjusted <a> s, machine free <f>% on average)`. A build, import, headless run or clip cut that neither logs a line nor uses CPU for 120 s is killed as stalled, and its error says `did not finish (<why>)`. The pings, the debugger check and `stop_project`'s grace stay in wall time.

## Start and stop a game

### `run_project`

- **Does:** launches the project with the bridge injected and returns once the bridge connects: `{session, projectPath, processId, quiet, version, recording?, prep, godot, window, warning?}` (`window` `{width, height}` the game window's size in pixels; `version` is the server's, `0.1.0+<sha>`, to quote in an issue; `godot` is the Godot executable it launched: `GODOT_PATH`, else a `Godot*console*.exe` found on `PATH`, the newest-named in the first folder that has one; with neither, the launch is refused with the `claude mcp add` line that sets `GODOT_PATH`). `restart_project`'s result carries `godot` too.
- **Use:** `projectPath` (the folder holding `project.godot`); `scene` for a scene other than the main one; `userArgs` (after `--`, read with `OS.get_cmdline_user_args()`); `engineArgs` (before `--`, e.g. `["--resolution", "1280x720"]`; the last `--resolution`, after `godot-mcp.json`'s `resolution`, gives the window exactly that size, even one larger than the screen, 1 to 16384 pixels a side, and a window that still differs adds `warning`: "--resolution asked for a WxH window and the game's window is wxh: the system did not give it the size asked for, so screenshots and input work in the window it has." A `--resolution` without a value, not `WIDTHxHEIGHT` or out of range is refused before launch. For a 2x capture of a `canvas_items` project, launch at twice its size); `options {quiet, shutOutRealGamepads, mute, session, prepare, preset, record, dropIdle}`; `mute: true` silences a watched run (`quiet: false`) by muting its Master bus for the whole session, again whenever the game unmutes it, and `restart_project` keeps it; `mute: false` on a quiet run is refused, since a quiet run is always silent.
- **Edges:** a live session name is refused when you pass it, or when the default name's live holder runs on the same folder; a default name held live by another folder becomes `<name>-2`, `-3`, …; a new name starts a second session alongside. `options.preset` names a preset from `godot-mcp.json` and fails when the file or preset is missing. By default the machine's real gamepads stay live and feed the same actions as the gamepad tools; `shutOutRealGamepads: true` keeps them out, at the cost of focus-out notifications to the game (a game that pauses on focus loss will). `record` changes game timing: see Recording. `dropIdle: true` (only with `record`; refused without it) makes each cut clip drop every frame identical to the one before, so the wall-clock time between tool calls, when nothing moves, leaves the clip and the action plays at real speed; such clips have no audio, and a deliberate still (a held pose, a dialog to read) collapses to one frame too.

### `attach_project`

- **Does:** on an armed folder with a dormant game, joins that game at once; otherwise injects the bridge plus a one-use attach file and blocks until a game started on the project after that connects: `{session, projectPath, quiet, version, window, joinedPid?}` (`window` `{width, height}` the game window's size in pixels; `joinedPid` the dormant game joined).
- **Use:** for a game `run_project` does not start: a second client, a `--server` run, a smoke script, the editor's Play button. Start the launch in the background delayed a second or two (`Start-Sleep 2; godot --path <project>`) just before this call, or launch within `waitSeconds` (1 to 600, default 60, load-adjusted) after it. For a game already running, `arm_project` the folder before it starts, then call this at any time. `options {quiet, shutOutRealGamepads, mute, session, pid}`: `pid` picks one of several dormant games; `mute` (left out: the arm's, else false) silences the game by muting its Master bus, and `quiet` mutes it too. After a detach the game goes back to the arm's mute, or to its own when it goes idle.
- **Edges:** with one dormant game and no `pid`, that game is joined rather than a new launch waited for; with several and no `pid`, and with a `pid` that is not dormant, the call is refused with the dormant games listed. Joins of different dormant games wait at once, beside each other and beside a plain attach; a second join of the same pid is refused naming the session that waits for it. A game started before `arm_project`, or on a folder not armed, has no bridge and never attaches: relaunch it while the folder is armed. `quiet: true` creates the window unfocused, then parks it off-screen and caps it at 60 fps, but only a launcher can put a game on the hidden desktop, so it shows on the primary screen for a moment at start (longer when a breakpoint holds it before the bridge's `_ready`); a joined dormant game is parked at the join. A quiet attach shares a folder only with quiet sessions. On a folder this server armed, `quiet` and `shutOutRealGamepads` left out take the arm's values, and a value that differs from the arm is refused. An attached session has no captured output (`get_debug_output` refuses it), and cannot be restarted; `detach_project` ends it leaving the game running, `stop_project` ends it and quits the game. The error feed starts at the attach: errors a dormant game raised before it are not reported.

### `detach_project`

- **Does:** ends an attached session and closes the connection; removes the injected `override.cfg` unless another live session uses the folder or it is armed. The game keeps running: on an armed folder it goes dormant again, letting go of any key, button or action the drive left held, so a later `attach_project` joins it again (a window a quiet join parked comes back on screen); otherwise its bridge goes idle.
- **Use:** to finish with a game `attach_project` joined and leave it running; `stop_project` quits it instead.

### `arm_project`

- **Does:** writes the injection `override.cfg` and `.godot/godot-mcp/armed.json`, so every game with a window started on the folder from now on (by a script, a launcher, by hand) carries a dormant bridge that `attach_project` can join while it runs; a `--headless` game (a smoke, a test runner) is left alone, so it is never joined by mistake: `{projectPath, quiet, shutOutRealGamepads, mute, dormant: [{pid, startedAt}]}`.
- **Use:** before launching games you may want to look at later (a smoke, `dtd.ps1 launch`, a player reaching a state), instead of a delayed launcher. `options {quiet, shutOutRealGamepads, mute}`, all false by default; every session on the folder must agree with `quiet` and `shutOutRealGamepads`, while an attach's `mute` may differ. A dormant game waits muted when the arm is `mute` or `quiet`, and gets its own mute back when disarmed.
- **Edges:** a game already running at the call has no bridge and is never listed. Arming again with the same options returns the state; with different ones it is refused (disarm first), as is arming a folder another godot-mcp server armed with other options. The arm lasts until `disarm_project` or the server exits. A quiet arm starts every game's window unfocused and parks it off-screen, a hand-launched one included. A dormant game checks for a join twice a second, even while paused, and registers no error logger until it is joined.

### `disarm_project`

- **Does:** ends an arm: `armed.json` is removed, and `override.cfg` too unless a live session uses the folder: `{projectPath, overrideRemoved}`. Dormant games stop waiting (a window a quiet arm parked comes back on screen); attached sessions stay attached, and their games go idle at their detach.
- **Use:** when you are done joining games on the folder.

### `stop_project`

- **Does:** asks the game to quit, kills it after 3 s (30 s for a recording run) of load-adjusted time, so a busy machine waits longer in wall time (at most 5 x), removes the override when no other live session uses the folder and it is not armed: `{session, projectPath, exitCode, killed, killReason?, overrideRemoved, alreadyExited, gameExitCode, leftRunning?, quitMs?, recording?, headlessHostStopped}`. `projectPath` in place of `session` frees a folder: it stops the warm headless host there (waiting for a headless call running on it) and the session running there, if one does; with `session` too both must name the same folder, and several live sessions there are refused, naming them. When only a host ran there the result is `{projectPath, headlessHostStopped: true}`; neither is refused. Stopping a session also stops its folder's warm host when that host is idle, and `headlessHostStopped` says whether one was stopped. `exitCode` is the process the server started (on Windows the `Godot_console` wrapper); `gameExitCode` is the game's own, null when it could not be read and whenever the game was killed (the code read after a kill is not the game's). The grace watches the game itself: a game that quits in time is not killed even when it left processes running, which `leftRunning` lists (`["PING.EXE (pid 1234)"]`) and which end with the wrapper, so `exitCode` is then -1. A kill says why in `killReason`: no answer to a ping, no answer to the quit request, still shutting down after the grace, or no bridge connection to ask. A kill after the grace also gives the grace in wall time and the machine's free share (`after 3 s of load-adjusted time (wall 8.4 s, machine free 36% on average)`), whether the bridge's connection was still open (the scene tree not yet freed, so a node's `_exit_tree` or the last frame held it) or had closed (the time went into the engine's or .NET's teardown), and the game process's CPU, threads and main-thread state over its last second, with its last stderr lines for a run. A game that quit gives `quitMs`, the wall milliseconds from the quit request until its process was gone: one near the grace is a quit about to become a kill.
- **Use:** at the end of every `run_project` session, and to quit a game `attach_project` joined. An attached game is stopped the same way through its own process (from the bridge's hello): `exitCode` is null, `gameExitCode` is the game's, `leftRunning` never appears, and the session is gone afterwards, not listed as stopped. A bridge that sent no process id is only asked to quit, and `warning` says it may still be running.
- **Edges:** `alreadyExited` is true when the run had ended before the stop: the game quit, crashed or was killed from outside (a debugger's stop); the exit code, not the flag, tells a kill from a quit, and a debugger picks that code. A game that does not answer a ping in 2 s is killed at once. A game a debugger is attached to is stopped all the same, and `warning` says its debug session ended with it. For a recording run, `recording` holds `{path}` (no marks: the full movie) or `{clips}` (one H.264 `.mp4` a mark pair; the full movie deleted), plus `error` when a cut failed. A clip whose encode failed (an ffmpeg without libx264, or the encode timing out) is a stream-copied `.avi` of the same frames instead, idle kept, and `error` says which; the other clips are still `.mp4`.

### `restart_project`

- **Does:** relaunches a run session with the scene, arguments and options it was started with, keeping its name, its error `seq` and its debug output (a marker line separates the two games).
- **Use:** after editing code or scenes, to pick up the change without losing the session; `options {prepare}`.
- **Edges:** the prep runs while the old game still runs, so a failed C# build is an error and leaves the old game running. To change the scene or arguments, `stop_project` then `run_project`. An attached session cannot be restarted. The old game is stopped as `stop_project` stops it, with its `warning` when a debugger was attached to it; `previousAlreadyExited` and `previousGameExitCode` (left out when unknown) say how it had ended, as `stop_project`'s `alreadyExited` and `gameExitCode` do, and `previousKillReason`, `previousLeftRunning` and `previousQuitMs` (each left out when empty) say how it was stopped, as its `killReason`, `leftRunning` and `quitMs` do. A recording run records the new game to a new file and returns the old one's outcome as `previousRecording`. `window {width, height}` is the relaunched game's window, as `run_project` reports it, and a window that differs from `--resolution` adds `run_project`'s size text to `warning`, after the debugger's.

### `list_sessions`

- **Does:** lists the live sessions by name (`includeStopped: true` adds the stopped ones): project folder, kind (`run` or `attach`), whether it is live, `processId` (the process `run_project` started, the `Godot_console` wrapper on Windows that `stop_project` ends; null for an attach), `gameProcessId` (the game's own process, the one a debugger attaches to; null until the bridge has connected), and a recording's state; `armed` lists the folders `arm_project` armed, each with its `quiet`, `shutOutRealGamepads` and `dormant` games (`{pid, startedAt}`) that `attach_project` can join; `headlessHosts` lists the warm headless hosts by folder, `{projectPath, pid, startedAt, requests, idleSeconds}` (`idleSeconds` 0 while one serves a call).
- **Use:** when a call is refused for want of a session name, or to find a session a previous turn started; `gameProcessId` for a debugger's attach. A stopped run is kept until its name is reused, with its last pids and output (`get_debug_output` and `restart_project` still reach it by name), and listed only with `includeStopped: true`.
- **Edges:** while a debugger is attached to the game, every runtime call first pings it for 500 ms of wall time and fails at once when the game does not answer: "The game (pid <pid>) did not answer within 0.5 s while a debugger is attached: it is most likely paused at a breakpoint. Continue it in the debugger, or retry if it was only busy." A call that times out on such a game says it is paused under a debugger rather than stuck.

### `get_debug_output`

- **Does:** the newest stdout and stderr lines of a session's run (the current or last one under its name), whether it still runs, and its exit code.
- **Use:** when the game crashed or quit, or a tool reports the connection ended. `limit` (1 to 500, default 100); `before` (a line number) pages back, starting from the returned `stdoutFirstLine` or `stderrFirstLine`.
- **Edges:** the server keeps the last 500 lines of each stream; lines over 1000 characters are cut. Structured errors are better read from `get_errors`.

## See the game

### `take_screenshot`

- **Does:** captures the game's next drawn frame to a PNG under `.godot/godot-mcp/screenshots/` and returns its path and size, plus an image.
- **Use:** `responseMode` `path_only`, `preview` (default, at most `previewMaxWidth` wide, 480 by default) or `full`; `crop {x, y, width, height}` in viewport coordinates, mapped to the screenshot's pixels: in a window stretched to twice the project's size, the PNG is twice the rectangle's size.
- **Edges:** the crop is in viewport coordinates (see Rules); a letterboxed window crops the same content, and a crop wholly outside the viewport fails as "the crop (x, y, w, h) lies outside the (W, H) viewport". `path_only` saves context when only the file matters. To keep the shot as a project file (a tracked picture), use `save_screenshot`: this tool writes only under the ignored `.godot/`. The capture is the root viewport's texture with every visible popup and tooltip on it: embedded ones (Godot's default) are in the texture, and in a project that sets `display/window/subwindows/embed_subwindows=false`, where each is its own OS window, they are pasted where the window shows them, at any stretch mode and window size. Every capture (baselines, frame steps, `wait_for`, `preview_scene`) does the same.
- **A before/after pair:** a game that animates (a flickering light, a moving sprite) draws a different frame each time, so two shots of one state differ outside the region under test. Pause it first: `frame_control {action: "pause"}`, shoot, make the change (`set_property`), shoot again, then `frame_control {action: "resume"}`. A paused game still draws a fresh frame for each shot, since the capture waits for the next `RenderingServer.frame_post_draw`.

  Pausing does not stop everything: a shader's `TIME` is "affected by time_scale but not by pausing" ([CanvasItem shaders](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/canvas_item_shader.html)), and a node whose process mode is Always keeps processing ("Paused or not, this node will process", [Pausing games](https://docs.godotengine.org/en/4.7/tutorials/scripting/pausing_games.html)), so crop those out.

### `save_screenshot`

- **Does:** `take_screenshot`'s capture, written to `path`, a file in the project such as a tracked picture, in one call. Returns `take_screenshot`'s result with `path` the named file and `capturePath` the copy under `.godot/godot-mcp/screenshots/`, beside which any preview stays, plus the image unless `responseMode` is `path_only`.
- **Use:** `path` (project-relative, `res://` or absolute); `crop` as `take_screenshot`'s; `options {overwrite, responseMode, previewMaxWidth}`, the last two as `take_screenshot`'s `responseMode` and `previewMaxWidth`. Missing folders are created.
- **Edges:** `path` must end in `.png`, resolve inside the project and not lie under `.godot/`; it is checked before the shot is taken. An existing file is refused unless `options.overwrite` is true. The refusals read "path must end in .png: <path>", "path <path> resolves outside the project <project root>; save inside the project", "path <path> is under .godot/, which the editor owns; pick a tracked folder" and "<path> exists; pass options.overwrite true to replace it"; a failed copy reads "saving the screenshot to <full path> failed: <message>".

  A link (junction or symlink) on the way is followed, and its target must also lie inside the project and outside `.godot/`; an existing target file that is a link to outside is refused even with `options.overwrite`. A `:` after the drive (an NTFS stream) and an 8.3 short name (`GODOT~1`) are refused, as is a `\\?\` path. Those refusals read "path must not contain ':' after the drive: <path>", "path <path> uses a short (8.3) name; use the folder's full name", "path <path> leads through a link to <resolved>, outside the project; save inside the project" (or "…, under .godot/, which the editor owns; pick a tracked folder") and "path <path> leads through a link at <link path> that cannot be followed: <message>".

  It is in the file-editing class (`edit-scene`), not `read`, so an agent allowed to edit no file does not gain this power, and `batch_drive` refuses it as a step.

### `get_ui_elements`

- **Does:** lists the game's Controls depth first: path, name, class, `rect` in viewport coordinates, visible, and where they apply `text`, `disabled` and `tooltip`. `text` is the text the Control shows, the one a `{text}` target matches: a Button's (CheckBox, OptionButton and MenuButton included), a Label's and a LinkButton's translated text (an `uppercase` Label upper-cased), a LineEdit's placeholder while it is empty (a `secret` one's secret character, once per character), a RichTextLabel's text without BBCode. An `ItemList`, `TabBar`, `TabContainer` (on its own entry) and `Tree` add `items`, the texts an `item` target matches: `{index, text, hidden?: true, disabled?: true}` for a flat list or tab bar (every entry `hidden` when its drawing list is not visible, a `TabContainer` with `tabs_visible` off included), `{path, text}` for each Tree item an `item.path` can reach (none hidden or under a collapsed item), at most 50, with `itemsTotal` beyond. A listed path or text can still be ambiguous to an item target when a hidden or collapsed item shares it.
- **Use:** before any click, to find a target by path or by the text it shows; `filter` keeps one engine class and its subclasses (`BaseButton`); `visibleOnly` (default true) skips hidden subtrees; `offset` and `limit` (1 to 500, default 100) page.
- **Edges:** Controls only; `get_scene_tree` lists every node.

### `preview_scene`

- **Does:** starts the project quiet on one scene in its own short-lived session, pauses it before the scene's first frame, waits two drawn frames, screenshots it and stops: `{scene, path, width, height, previewPath?, cameraAdded, prep, errors?}` and the image.
- **Use:** after a headless scene edit, to see the result. `projectPath`, `scene` (ending `.tscn`, `.scn`, `.escn`, `.res` or `.tres`), `options {resolution, prepare}` (`resolution` as `WIDTHxHEIGHT`, given exactly as `run_project`'s `--resolution` is), `responseMode`, `previewMaxWidth`.
- **Edges:** the scene's `_ready` and the project's autoloads still run; when one changes scenes, the result's `scene` says what was shown. A 3D scene with no current camera gets a temporary one framing its visible geometry (`cameraAdded: true`). The scene's ending is checked case-sensitively. Prep, launch and capture share 60 s of load-adjusted time. It cannot run inside `batch_drive`.

## Scratch scenes

### `run_scratches`

- **Does:** plays each scratch scene in its own fresh headless game session, `parallel` at a time (default one after another), walking its steps itself, and gives each a verdict: `{passed, green, red, known, noSteps, killed, prep: {build, buildMs?, buildLog?, import, importMs?, importLog?, note?}, scenes: [{scene, verdict, steps: {played, total}, pace, paceReason?, seconds, session, failedAt?: {index, name, error, status, pattern?: {pattern, reason?}}, failures?: [{index, name, error}], alone?, aloneFailedAt?, details?: [{index, name, ok, error?, gameMs, status, errors: [{message, file, line}], lines}], exit: {code, leaked?, lines?, error?, killed?, killReason?, warning?}, known?}]}`. A scratch scene's root implements the **scratch protocol**: `PlayStep(int)`, `GetStepCount()`, `GetStepName(int)` and `GetStatus()`. Per step the server calls `PlayStep`, waits the scene's **pace** in game time (`wait_for {gameMs}`), then reads `GetStatus()` (its second line is `status`). A step fails on an error from the call, an engine error, `push_error` or C# exception in the error feed since the step began (never a text search), or a stdout or stderr line in the step's window matching one of the project's `scratch.patterns`; the scene stops at the first failed step unless `options.keepGoing`. `failedAt` is the first failed step and `failures` lists every failed step in order (`index`, `name`, `error`; one entry without `keepGoing`), both absent for a scene with no failed step, and each failed step in `details` carries its `error`. A killed scene's `failedAt` names the step the kill cut off, also the last entry of `failures`. After the last step and that step's pace once more the game is stopped gracefully and its stderr read for the leak line (`N ObjectDB instances were leaked at exit`). Verdicts: `green` (every step clean, exit 0, no leak), `red`, `no-steps` (`GetStepCount()` is 0), `known` (a `known` scene that went red), `known-now-green` (counts as red until its `known` entry goes), `killed` (past its ceiling or stuck). `passed` is true when nothing is red or killed. `details` (the per-step list, each step's `lines` at most 20 then `… N more`) comes for a red or killed scene, or for every scene with `options.details`.
- **Use:** in place of a project's `Run-Scratches.ps1`. `projectPath`, `scenes` (scene names in `scratch.folder`, or `res://` paths; left out: every `.tscn` directly in `scratch.folder`, in name order), `options {pace, userArgs, prepare, details, parallel, session, keepGoing}`: `pace` in seconds (above 0, at most 120) for every step of every scene of this call, step paces of the profile included,

  `parallel` 1 to 4 (overrides the profile's), `userArgs` appended after the profile's, `prepare` `auto` (default) or `never`.

  `keepGoing` true (default false; no profile key) plays a scene's next step after one that failed on a pushed error or a matching line, so independent red steps are all reported; a step whose own call failed (the game gone or stuck) still stops the scene. Steps are usually stateful and sequential, so off is the default. With `keepGoing` the wait after the last step runs and the exit is judged too.

  The project's `godot-mcp.json` holds the rest in a `scratch` section, parsed strictly: `folder` (project-relative or `res://`, exact case; required when `scenes` is left out), `userArgs` (used in place of the top-level `userArgs` for scratch runs),

  `pace {<Scene>: seconds | {seconds, reason}}` (default 0.5; the object form takes both keys and an optional `steps {<step>: seconds | {seconds, reason}}` of paces for single steps, each key a step's index written plainly (tried first; `03` or `+3` is a name) or its name, so one slow step does not make every step wait;

  it says why the scene needs that pace, and the reason comes back as `paceReason` on a `red` or `killed` scene whose pace came from the profile, the failed step's own reason when that step has a pace of its own (none when its pace is a bare number), since a step that ran into the next is usually a pace set too short),

  `known {<Scene>: reason}`, `patterns` (case-sensitive regexes, each a string or `{pattern, reason}` with both keys; a step failed by a matching line names the first matching entry as `failedAt.pattern`, with its reason; default `^SCRIPT ERROR|^ERROR:|ObjectDB instances? (was|were) leaked`; `[]` turns line matching off), `parallel` (1 to 4, default 1).

  A `steps` key matching no step, a name matching more than one step, or two keys naming one step makes the scene red before it plays (names are known only after launch). The wait after the last step uses that step's pace, and the ceiling sums each step's pace plus 10 s, plus the last step's pace and 10 s for the markers.

  Scenes start `parallel` at a time: those listed in `scenes` in that order, a folder run's largest pace (a scene's or a step's) first (equal paces in name order), so a slow scene does not start last and end the run alone; the result keeps the order given, name order for a folder run.

  With `parallel` above 1, a `red` or `killed` scene (not `known`, not one red before any step played, a boot error included) is played once more alone after the others finish: `alone: true` when that replay is green (the entry is the replay's and counts as green), else `alone: false` with the first run's entry and the replay's failure as `aloneFailedAt`; `seconds` covers both runs. An alone replay plays the scene again with the same `keepGoing`; `aloneFailedAt` is its first failed step.
- **Edges:** the prep runs once for the whole run, so a stale C# assembly is built, and a red build refuses the whole run; `prep` is the block `run_project` reports (`build` and `import` `skipped` with `prepare: never`). Each scene is a game session named `<folder>.scratch-<scene>`, or `<options.session>.scratch-<scene>` when `options.session` names the prefix (give each worktree's agent its own, so parallel runs are told apart in `list_sessions`), (numbered `-2`, `-3`, … when another session holds that name), still listed as stopped afterwards so `get_debug_output {session}` reads its output; its stdout and stderr carry the runner's own `[godot-mcp] scratch … end <nonce>` marker lines, which end each window and are never judged. The root is the game's current scene once started, whatever it renamed itself to; a root missing a protocol method, a scene with no current scene, or a launch that fails is `red` at `failedAt.index` -1, even for a `known` scene. The **boot** (from the launch to the first step) is judged by the error feed alone: an engine error, `push_error` or C# exception there (in the scene's `_ready`, say) makes the scene `red` at `failedAt {index: -1, name: "boot", error: "<message> (<file>:<line>)"}` with no step played and no `details`, even with `options.details`, even for a `known` scene, and it is never played again alone; a scene with no steps that errors at the boot is `red`, not `no-steps`. A warning at the boot is not; lines printed before the first step are never judged, and `scratch.patterns` never apply to them. A step's ceiling is each step's pace + 10 s, the last step's pace once more, and 10 s for the markers, in load-adjusted time; past it, or when the game stops answering, the scene is `killed` and its game stopped. An error or a failed wait in the pace after the last step, or a stop that had to kill the game, turns an otherwise green scene red, with the reason in `exit`. A pattern that takes over 1 s on a line fails that step naming the pattern. A project with `application/run/flush_stdout_on_print.debug` off buffers stdout, so the markers never arrive: the error says so. `--scratch-auto` is refused in any user arguments: the server walks the steps. It cannot run inside `batch_drive`.

## Drive input

All input tools answer `{pointer, heldButtonMask}` once the gesture has ended and two more frames have run; `click`, `drag`, `mouse_button` and `scroll` also say what they hit, each Control as `{path, class}` or null over none, a popup's included. One input call plays at a time per session. A target is `{element}` (a node's path, name or `%UniqueName`, as under "Paths"), `{text}` (the visible Control showing that text, as `get_ui_elements` reports it: trimmed, case-sensitive; `under` names a node that scopes the search to itself and its descendants) or `{x, y}` in viewport coordinates, exactly one of them. A text target that matches nothing is refused as `no visible Control shows 'Host'`, followed by up to five near misses (equal ignoring case, or containing) and each node named `Host` with what it shows (`…/Host is named 'Host' and shows 'New Game'`); one that several Controls show is refused listing up to ten with their rects, `narrow it with under`. A text match is aimed at as its Control would be, and `aimedAt` gains `matched {by: "text", text}`. A matched Control with an `owner` that does nothing on a press (one that ignores the mouse, or any `Label` or `RichTextLabel`, such as a card's title, whatever its mouse filter) takes a press landing on a Control of its own scene instance in the same window (its `owner`, or a Control that owner owns that is not itself the root of another scene instanced inside), and `pressedOn` names that Control. A match that acts on a press itself (a Button) and is covered is refused as covered, as is any match covered by a Control with no `owner` (one a script made with `new`) or by a popup's Control. Beside `element` (or `text`), `item {text | index | path, column?}` aims at an item drawn inside an `ItemList`, a `TabBar`, a `TabContainer` (its tab bar) or a `Tree`, at the item's rect centre (a Tree's column 0, for an item that folds, past the fold arrow's indent, so it is selected, not folded, and refused when the indent fills the column; a right-to-left ItemList where Godot mirrors it): `text` is the item's text as drawn (translated as the Control's auto-translate mode says; exact, trimmed, case-sensitive; in a Tree, at any depth in `column`), `index` its index (an ItemList item or a tab; not a Tree), `path` a Tree item's column-0 texts from the first shown level down, visible items only, every branch reading a step followed (only several matches at the last step are ambiguous), `column` a Tree's cell (default 0); exactly one of `text`, `index`, `path`, and a blank `text` is refused. Before anything is pressed the point is checked back through the Control's own lookup (`get_item_at_position`, `get_tab_idx_at_point`, a Tree's item and column at the point); `aimedAt` then has `kind: item`, the list Control's `path` and `class`, and `item {index, text, path?, disabled?}` (a Tree item's `index` is its place among its siblings; a disabled item or tab is still pressed and says `disabled: true`). Refused with nothing pressed: another class (`… is a Label; item targets take an ItemList, TabBar, TabContainer, Tree, OptionButton, MenuButton or PopupMenu`), `path` or `column` off a Tree, `index` on a Tree, no such item (listing up to ten shown texts), several items with that text (listing each index and rect, `narrow with item.index`, or each Tree path, `narrow with item.path`; Tree siblings sharing one path are told to aim with `{x, y}` inside a listed rect), a hidden tab or Tree item (and a TabContainer whose tabs are hidden), an item under a collapsed Tree item (naming the outermost one: expand it first), an item scrolled outside its list's visible rect, which leaves out a Tree's column-title row and any visible scroll bar (both rects given: scroll the list first), an item whose point lies outside the viewport, such as a tab past a `clip_tabs`-off bar's edge (its rect, point and the viewport's size given: bring it into view first), a tab scrolled out of a clipped tab bar's drawn range (`… is scrolled out of the tab bar: tab 7 lies after the drawn tabs (0 to 2); scroll over the tab strip, scroll {target: {x, y}, direction: "down", notches: 5}, then try again`: follow it, repeating while the tab is not drawn, since a wheel notch moves the bar's offset by one tab; for a TabContainer the point is its tab strip's; a bar with `scrolling_enabled` off names its increment or decrement arrow's point and how many clicks instead), and a tab or item not laid out yet (`has no drawn rect`). The press must land on the Control that draws the item (the tab bar for a TabContainer), never on one of its scroll bars. Beside an `element` (or `text`) naming an `OptionButton`, a `MenuButton` or an open `PopupMenu` (an element names a `PopupMenu` only with `item`, and `offset` there is refused: `offset aims inside a world node; <path> is a PopupMenu.`), `item {text | index}` aims at an item of its popup: `index` counts separators, as `OptionButton.selected` does; `text` matches the drawn text as above, a miss listing up to ten item texts (separators left out) and several matches listing their indices (`<popup> has 2 items reading 'Save': index 1, index 4; narrow with item.index`); `path` or `column` is refused (`<path> is a <class>; a popup item takes text or index, not item.path`). In the refusals below `<popup>` is the `PopupMenu`'s path, or `the popup of <button path>`, and an item is its text quoted, or `item <index>` when it has none. A `PopupMenu` exposes no item rect, so the point is found by real mouse motions over the popup's items, bisecting on y and reading `get_focused_item()` after each (at most 2 x ceil(log2(items)) + 4 motions); the pointer ends on the item, highlighted as a player's pointer leaves it. A `click` or `mouse_button` press on an item of a closed `OptionButton` or `MenuButton` popup first clicks the button (a real press and release at its centre, hit-checked as any click), waits up to 1000 ms for the popup to show, then aims, and `aimedAt` gains `opened: true`; an open popup is never clicked again, since a press on its button would close it. A popup item's `aimedAt` has `kind: item`, the named node's `path` and `class`, and `item {index, text, submenu?}`, with no `viewport` when the named node is the `PopupMenu` itself; `pressedOn` names the internal `PopupMenuItems` Control that draws the items. An item with a submenu takes two calls: `click`, `hover` and a `mouse_button` press or move hold the pointer on it until the submenu shows (within its `submenu_popup_delay` plus 1000 ms), press nothing, and report the submenu `PopupMenu`'s path as `aimedAt.item.submenu`; the next call names that path as `element` with its own `item`. A `mouse_button` release on a submenu item is sent, so no button stays held. Refused with nothing pressed on the item: a separator (`'---' in <popup> is a separator; Godot ignores a press on it`); a disabled item (`'Load' in <popup> is disabled; Godot ignores a press on it`), since `get_focused_item()` reads -1 over it and the aim cannot be confirmed; a native popup (`<popup> is a native menu, an OS window of its own, and input events cannot reach a native menu; a popup is embedded only while gui_embed_subwindows is on (display/window/subwindows/embed_subwindows) and its force_native is off`); a `PopupMenu` named itself that is not open (`<popup> is not open; open it first`); a popup filtered by its search bar, a submenu of a filtered popup, and a popup whose hidden search bar still holds text (`<popup> filters its items by the search 'lo'; hidden items cannot be told apart, clear the search first`, naming the popup whose search filters; a search is the only thing that hides a popup item, since `PopupMenu` binds no item visibility); a disabled `OptionButton` or `MenuButton` whose popup is closed (`<path> is disabled; it cannot open its popup`); an item of a closed popup aimed by `hover`, `scroll` or a `mouse_button` move or release (`the popup of <path> is closed; click the button first`); a closed popup while another popup is open (`the popup of <path> is closed and <open popup path> is open, so the press that would open it only closes that one; close it first`); a drag from or to a popup item (`from: an item in a popup cannot start or end a drag; click it instead`); a popup that does not show (`clicking <path> did not open its popup within 1000 ms`); a probe that does not find the item (`could not find 'Save' in <popup> within 8 motions; get_focused_item read [0, 2, -1, …]`, ending `; it may lie below the popup's visible items: scroll the popup first`, or `above`, when every item read lies before it, or after it); a popup that closes while the pointer looks (`<popup> closed while the pointer looked for 'Save'`); a popup with no items inside the viewport (`<popup> draws no items inside the viewport`); and a submenu that does not show (`'Recent' in <popup> did not open its submenu <path> within 1200 ms`). A refusal that comes after the gesture opened the popup ends with `; the popup is open now`, and the popup stays open. An element is a Control, aimed at its rect's centre where it shows (through its CanvasLayer, a Camera2D's canvas transform, a `SubViewportContainer` and an embedded window's offset), or a 2D or 3D world node, aimed at its origin, or at `offset {x, y}` (a 2D node, local pixels) or `offset {x, y, z?}` (a 3D node, local units) from it, through its CanvasLayer or Camera2D, or projected through its viewport's current Camera3D; a node inside a SubViewport is carried out through its `SubViewportContainer` to the root. Every element target adds `aimedAt {x, y, kind: control | node2d | node3d, path, class, viewport?}` (`viewport` when the node is not in the root viewport; a `drag` answers `aimedAt {from, to}`, a point end null). A Control whose centre lies outside the viewport is refused, nothing pressed, with its rect and centre (bring it into view, or click by `{x, y}` inside its visible part), and one whose centre lies outside its SubViewport or embedded window with that level's rect; a Control in a native window is never refused so. A world node is refused, nothing pressed, when it projects outside its viewport's visible rect or its embedded window, sits behind its camera, has no current Camera3D, lives in a SubViewport shown without a `SubViewportContainer` (only a container forwards input) or in a native window, or when an embedded window, or a Control whose mouse filter is Stop on the hovered chain, would take the event before physics picking (a `scroll` passes a Control whose `force_pass_scroll_events` is on, the default); a press, drag, scroll or `mouse_button` press or release into a SubViewport whose `gui_disable_input` is on is refused, and `hover` or a `mouse_button` move may still aim at a world node there. Physics picking needs the node's viewport to have `physics_object_picking` on: the root takes the project setting, a SubViewport defaults to off; a project with `display/window/subwindows/embed_subwindows` off picks only once the window system has seen the pointer over the window. A handler that calls `accept_event()` on the way cannot be foreseen. `pressedOn` names the `SubViewportContainer` for any target inside it. An `{element}` is checked before any event is sent: a hidden node, a node being freed, or a bare name that several nodes share (listing their paths) is refused. Then, after the gesture's first motion to the aim point, the Control Godot hovers there must be the target, one of its children or, for a target that ignores the mouse, the ancestor that takes its clicks. Otherwise nothing is pressed and the call fails naming what covers it, with both rects. This applies to a click, a drag's start, a hover, a scroll and a `mouse_button` press or move; a drag's end may be covered. A tooltip showing over the centre counts as covering it. Aim by `{x, y}` inside the visible part instead.

### `click`

- **Does:** moves the pointer to `target`, presses, releases a frame later: `pressedOn` and `releasedOn` name the Control under the press and the release (with `doubleClick`, the second click's).
- **Use:** `target`, `button` (`left`, `right`, `middle`; default `left`), `doubleClick`.
- **Edges:** on an item of a closed `OptionButton` or `MenuButton` popup, the button is clicked first (`aimedAt.opened`), and on an item with a submenu nothing is pressed (`aimedAt.item.submenu`), as "Drive input" says. A showing tooltip is closed before the press (as `drag` and a `mouse_button` press do). The engine closes it on the press too (4.7.2 `viewport.cpp` L2011), but its removal lands a frame late, and the tooltip, not the Control beneath, would be reported as hit. A raw `simulate_input` press leaves the closing to the engine.

### `drag`

- **Does:** presses at `from`, moves in a straight line to `to` over `durationMs` (default 300, at least 3 frames; in a recording, clip time: 60 movie frames a second, however slowly the game runs), each motion carrying the held button, releases at `to`. `pressedOn` and `releasedOn` name the Control under the press and under the release point (not the one Godot sends the release to, which is always the pressed one), `guiDragStarted` whether Godot's GUI began a drag, `dropAccepted` whether a Control took the drop.
- **Use:** drag and drop, sliders, panning; `button` as `click`.
- **Edges:** Godot starts a GUI drag only once the path passes `gui/common/drag_threshold` (10 px by default); a shorter drag is a click.

### `type_text`

- **Does:** types `text` into the focused Control, one key press and release a character on a US layout; `\n` is Enter, `\t` Tab.
- **Use:** after a `click` on a LineEdit or TextEdit gives it focus.

### `key`

- **Does:** taps, presses or releases one key: `key` is a Godot Key constant without `KEY_` (`Enter`, `Escape`, `Space`, `A`, `F1`, `Up`), `action` `tap` (default), `press` or `release`, `modifiers` any of `shift`, `ctrl`, `alt`, `meta`.
- **Use:** shortcuts, `ui_accept`/`ui_cancel`, holding a movement key (`press`, then later `release`).
- **Edges:** a printable key carries the character it types unless `ctrl`, `alt` or `meta` is held.

### `mouse_button`

- **Does:** moves to `target`, then presses or releases `button` (`action` `press` default, or `release`), or with `action` `move` only moves, pressing nothing and closing no tooltip (`button` ignored); held buttons stay in later motions' `button_mask`. A press answers `pressedOn`, a release `releasedOn`, a move `hoveredOn`.
- **Use:** a drag by hand: `mouse_button` press, `simulate_input` `mouse_motion` events, `mouse_button` release; for paths `drag` cannot draw. `move` to hover without waiting for a tooltip; `hover` waits for it.

### `hover`

- **Does:** moves the pointer to `target` (an element or a point) pressing nothing, held buttons kept in the motion, then, when Godot has a tooltip to show for the pointer, waits for it to show. That tooltip is the hovered Control's, or else the nearest ancestor's, climbing no further than a Control whose mouse filter is Stop or which is top-level (4.7.2 `viewport.cpp` L1566-1596). Returns `{pointer, heldButtonMask, hoveredOn, tooltip, warning?}`: `hoveredOn` the Control under the pointer (`{path, class}`, null over none), `tooltip` `{text, x, y, width, height, owner}` in viewport coordinates (`text` null for a custom tooltip with no Label; `owner` the Control whose tooltip it is, `{path, class}`), or null.
- **Use:** checking a tooltip's text or look: hover, then `take_screenshot` with the returned rect as its `crop`. `options {tooltip, timeoutMs}`: `tooltip: false` answers right after the move; `timeoutMs` 0 to 10000, by default `gui/timers/tooltip_delay_sec` plus 1 s; in a recording, clip time (60 movie frames a second).
- **Edges:** Godot starts a tooltip's timer only from a motion over a Control that can process (4.7.2 `viewport.cpp` L2117, L2136), so over a pausable Control in a paused game `hover` answers at once with `tooltip: null` and the warning "the game is paused and <path> cannot process, so its tooltip timer never starts; resume, hover, then pause". A timer once started fires even if the game pauses after, so hover, then `frame_control pause`, keeps the tooltip up. A tooltip due but not shown in time answers the warning "no tooltip showed within <n> ms". Over a Control with no tooltip, and none on the ancestors that climb reaches, it answers at once, no warning. A `MenuBar` title's tooltip and an embedded `PopupMenu` item's are read, with a point target or an item target on the open popup (a `PopupMenu`'s items are drawn by its internal `PopupMenuItems` Control, which an element target cannot name, and which `tooltip.owner` reports, the `PopupMenu` two parents up); a native, non-embedded `PopupMenu` is out of reach. The hover stays on the injected pointer, from `hover`, `mouse_button` or a `drag`'s end, through the game's own `update_mouse_cursor_state`, a drop's end and a scene change, until a real mouse motion hands it back; a game that re-picks every frame sees one `mouse_exited`/`mouse_entered` pair per frame, and a physics `input_event` sees the bridge's re-pick motions as it sees the engine's own hover pick.

### `scroll`

- **Does:** closes a showing tooltip, moves the pointer to `target` (hit-checked as a press is, held buttons kept in the motion), then plays `notches` (1 to 100, default 1) notches one frame apart in `direction` (`up`, `down` default, `left`, `right`). A wheel notch is a press and a release of the wheel button in the same frame, both carrying `factor`, as Godot's Windows display server sends one (4.7.2 `display_server_windows.cpp` L6472-6499, L6577-6585); the wheel never joins `heldButtonMask`. Returns `{pointer, heldButtonMask, scrolledOn}`: the Control under the point (`{path, class}`, null over none).
- **Use:** scrolling a `ScrollContainer`, a long `ItemList` or log, or a game's wheel zoom. `options {factor, via}`: `factor` more than 0 and at most 10 (default 1, one standard wheel notch); `via` `wheel` (default) or `pan`, which sends each notch as one `InputEventPanGesture` whose delta is the direction times `factor` (down and right positive), as a trackpad does.
- **Edges:** a `ScrollContainer` moves an eighth of its page per notch times `factor`, or per pan delta of 1 (4.7.2 `scroll_container.cpp` L185-230, L311-320). A child with mouse filter Stop swallows wheel events unless its `force_pass_scroll_events` is on (4.7.2 `viewport.cpp` L1763), so `scrolledOn` may name that child while nothing scrolls; a pan gesture goes to the Control under the point whatever its filter.

### `simulate_action`

- **Does:** injects an InputMap action: `{pointer, heldButtonMask}` as `simulate_input` returns.
- **Use:** driving a game by its actions (`jump`, `ui_accept`) instead of the keys bound to them. `action`, `options {mode, strength}`: `mode` `tap` (default: press, a frame, release, as `key` taps), `press` or `release`; `strength` 0 to 1 (default 1), carried by the press.
- **Edges:** an action missing from the project's InputMap is refused. A pressed action stays held until released. It goes through `simulate_input`'s `action` event, so a raw sequence can still mix actions with other events there.

### `capture_input`

- **Does:** `mode: "start"` begins capturing the session's input; `mode: "stop"` ends it and returns `{events, count, truncated, ended?}`, the events in `simulate_input`'s format (`key`, `mouse_button` with wheel notches as `wheel_*` buttons and their `factor`, `mouse_motion`, `pan_gesture`, `joypad_button`, `joypad_motion`, `action`), with a `wait {ms}` before any event 20 ms or more after the one before, timed on the game's own clock. Feed `events` to `simulate_input` to replay them.
- **Use:** `options {sources, motion}` with start only: `sources` any of `real` (a person's input to the game's window) and `sent` (every event the server's input tools play, pads included), both by default; `motion` keeps mouse motions with no button held (false by default; a drag's motions are always kept, so it replays as a drag). To record a person playing, run with `options.quiet: false` or attach, start, let them play, stop.
- **Edges:** a quiet session (a run, or an attach with `quiet: true`) gets no real input, so it captures `sent` only and start's result says so in `warning`. A gesture comes back as its raw events (a `drag` as a press, motions and a release; `type_text` as keys). Capture stops at 2000 events, waits included, with `truncated: true`. A capture survives its game: after a stop, restart or crash, `capture_input stop` naming the session returns what was captured before, with `ended` (`stop`, `restart`, `exit`). Only one capture runs per session; a second start is refused. The extra mouse buttons and gestures other than a pan are not captured, since `simulate_input` cannot play them.

### `simulate_input`

- **Does:** sends raw `events`, one frame apart: `key`, `mouse_button` (`button` `left`, `right`, `middle`, or a wheel notch `wheel_up`, `wheel_down`, `wheel_left`, `wheel_right` with `factor?`, default 1), `mouse_motion`, `pan_gesture {x, y, delta_x?, delta_y?}` (a trackpad pan, deltas 0 when left out), `joypad_button`, `joypad_motion`, `action` (an InputMap action with `pressed?`, `strength?`), `click_element`, `wait {ms}`.
- **Use:** input actions directly, curved mouse paths, precise event timing. A `wait {ms}` is game time that `time_scale` does not stretch, so in a recording it lasts its length in the clip however slowly the game runs. An omitted `pressed` on a key, mouse or pad button is a press and a release a frame apart, on a wheel button both in one frame as `scroll` sends them; a wheel button never joins the held buttons. A motion's `relative` and `button_mask` default from the pointer and held buttons.
- **Edges:** `x`, `y` are viewport coordinates as everywhere.

### `stress_input`

- **Does:** fires `count` random inputs, one a bridge call, each drawn uniformly and seeded from `pool`, and reports `{survived, seed, iterations, stoppedAt?, drawn {actions, keys, elements}, errors, skipped}`. An action is tapped as `simulate_action` taps it, a key as `key` taps it, an element clicked as `click` clicks it. `errors` lists each new error once, keyed by message, file and line, with the `iteration` it first appeared at and its `count`.
- **Use:** `pool {actions?, keys?, elements?}` (1 to 200 entries in all), `count` (1 to 1000, default 100), `seed` (0 or more; left out, one is drawn and returned), `options {gapMs}` (0 to 5000 milliseconds after each input, default 0, of game time `time_scale` does not stretch: in a recording, clip time). The same seed and pool replay the same sequence, so a failing run is reproduced by passing its `seed` back.
- **Edges:** a draw the bridge refuses (an action missing from the InputMap, an element hidden at that moment, an unknown key) does not end the run: it is counted under `skipped` with the bridge's reason, the iteration it was first refused at and its count. The run stops at the first input the game does not answer, with `survived: false` and `stoppedAt`; otherwise `survived` means the game still runs and answers a ping at the end. It cannot run inside `batch_drive` (a thousand inputs outrun its deadline), and its result has no ordinary `errors` key: the run's own `errors` replace it. In a recording, each input's reply is waited on in clip frames, as the input tools' is, so a slow recorded game does not end a gapped run early.

### `gamepad_button`

- **Does:** taps, presses or releases one pad button as a pad's driver would: `button` a JoyButton without `JOY_BUTTON_` (`A`, `B`, `START`, `DPAD_DOWN`, `LEFT_SHOULDER`...), `action` `tap` (default), `press` or `release`, `device` 0 to 15. Without `device`, all three pad tools (and `simulate_input`'s `joypad_*` events without one) inject on the lowest id no connected real pad holds, keep that id for the game's life while it stays free, and report it as `device`; claim that pad in a game's pad-selection step as a player would.
- **Use:** actions bound to pad buttons; the d-pad moves GUI focus through the default `ui_*` bindings.
- **Edges (all three pad tools):** the injected pad never shows in `Input.get_connected_joypads` (only the real pads do), so a game that waits for a connected pad needs an OS-level virtual pad. An explicit `device` a real pad holds is injected as asked, with a `warning` naming the pad; with real pads on all 16 ids and no `device`, the call is refused. Real pads also feed the game unless the session was started with `shutOutRealGamepads`, which costs focus-out notifications to the game (a game that pauses on focus loss will) and leaves popups (menus, `OptionButton` lists) open, as `run_project`'s edges say.

### `gamepad_axis`

- **Does:** moves one axis: `axis` (`LEFT_X`, `LEFT_Y`, `RIGHT_X`, `RIGHT_Y`, `TRIGGER_LEFT`, `TRIGGER_RIGHT`), `value` (-1 to 1 for sticks, Y down-positive; 0 to 1 for triggers), `device`, `options {durationMs, release}` to sweep and then let go.
- **Use:** triggers, analogue strength past a deadzone.

### `gamepad_stick`

- **Does:** pushes `stick` (`left` or `right`) to `position {x, y}`, both axes each frame; `device`, `options {durationMs, release}` (`durationMs` in a recording counts clip time, 60 movie frames a second, however slowly the game runs).
- **Use:** menu navigation with a stick, character movement.
- **Edges:** a push moves GUI focus once, on the change from released to pressed; the next move needs a release first (`options.release: true`, or a push to `0, 0`).

## Time

### `frame_control`

- **Does:** `action` `pause` or `resume` sets `SceneTree.paused`; `step` advances exactly `count` (1 to 1000, default 1) drawn frames, or physics ticks with `options.unit: "physics"`, and leaves the game paused; `time_scale` sets `Engine.time_scale` to `scale` (above 0, at most 100). Returns `{paused, timeScale, processFrames, physicsFrames}`.
- **Use:** freezing the game to inspect it; `step` with `options.screenshot: true` to capture the exact frame reached; `time_scale` to fast-forward a slow sequence.
- **Edges:** nodes whose `process_mode` ignores pause keep running. A step counts drawn frames, so it is refused while the window is minimized or in low-processor mode, and a step whose frames stop being drawn fails at its deadline (10 s + 100 ms a frame, load-adjusted), leaving the game paused. A step fails if the game pauses itself midway. While a step or a `capture_frames` runs, other steps, `pause` and `resume` are refused.

### `capture_frames`

- **Does:** saves the game's frame at each of a list of moments in one call, with no round trip per frame: `{folder, files, width, height, points: [{at, frame, file, gameSeconds, late}], shared, stopped?, missed?, call?, start?}`, paths only, no images. `folder` is the directory of the PNGs and `files` names each distinct one once, in the order first taken; a point's `file` is its index into `files`, `frame` the engine frame it was taken in, and `shared` counts the points that took a file an earlier point took (a game running slower than the points are spaced shares frames). A capture stopped before its first point has empty `files` and `points` and no `folder`, `width` or `height`.
- **Use:** frames at set points of an animation or a timer-driven sequence. `at` (1 to 1000 ascending seconds, each 0 to 120), or `options {every, for}` for evenly spaced points (`every` 0.5 with `for` 1.2 gives 0.5 and 1.0); `options.crop` as `take_screenshot`'s. The seconds are game time from the call's start, the sum of each frame's delta, so they follow `Engine.time_scale` as the game's own timers do. `options.call {node, method, args?}` calls a method in the clock's first frame, before the nodes process it, so the points count from the method's entry with no round trip between: capture the frames of an effect the method starts. A coroutine is not awaited (it runs to its first `await`), and the result adds `call: {value}`, its return value as `call_method` returns it (`{valuePreview, valueLength}` past 2000 characters). Or `options.call {tool, args?}` calls a game tool, a C# method the game marks `[GodotMcpTool]`, by its name as `list_game_tools` lists it, with `args` an object keyed by parameter name as `call_game_tool` takes it; the result's `call` is then `call_game_tool`'s `{tool, value, type, build?}`, and a tool that returns a `Task` is not awaited: `call` reads `pending: true` with a null `value`. A call refused as `call_method` or `call_game_tool` refuses it, or an error it raises, fails the capture with no frames.

  `options.start {node, property, equals | exists | expression, edge?, timeoutMs?, then?}` is a condition laid out as `wait_for`'s, of kind `exists`, `property` or `expression`, that the clock waits for: the points count from the frame it is met, not from the call, so a round trip after a `wait_for` does not shift them. `start.then {call?, timeScale?}` runs in the met frame as `wait_for`'s `options.then` does (`call` first, then `timeScale`), and the capture's own `options.call` runs after it, in that frame, where the clock starts. A start already true at the call starts the clock at the next process frame, as a capture without one. Another kind is refused: `options.start takes an exists, property or expression condition; this condition is {kind}.` A bad `start.timeoutMs` or `start.then` is refused with `wait_for`'s texts (`timeoutMs must be between 0 and 120000.`, `options.then needs call, timeScale or both.`).

  The result adds `start: {met: true, frame, then?, failedChecks?}`, `frame` being `Engine.get_process_frames()` where the start was met. `start.timeoutMs` counts real time (not load-adjusted, and not clip time in a recording), defaults to 10 s (0 checks once, at the call) and is added to the capture's allowance, at most 600000 ms in all. A start that times out is still a success: `stopped: true`, empty `points` and `files`, `missed` every point, and `start: {met: false, last}`.
- **Edges:** a point is taken in the first frame at or after it, and `late` says by how many seconds; points due in the same frame share one file. Refused while the game is paused (its game time does not advance; step it with `frame_control` and `options.screenshot` instead) and while a `frame_control` step runs; while it runs, `pause`, `resume`, a step and another capture are refused. It ends at `options.timeoutMs` (default the last point + 10 s + 100 ms a point, load-adjusted; 1 to 600000) and then answers the frames taken with `stopped: true` and `missed`, the points not reached, still a success: under a small `time_scale`, raise `timeoutMs`. A game that pauses itself partway stops its clock, so it ends the same way. A call refused as `call_method` refuses it, or a method that raises an error (a GDScript runtime error or C# exception cannot be caught, so the bridge's error feed is read across the call), fails the capture with that error and no frames; an unrelated error another node raises in that same frame fails it too.

### `watch`

- **Does:** samples properties and expressions of the running game once a frame over a window, beside every other tool, and returns each track's change points. `action` `start` begins a watch and answers after its first frame with `{startFrame, tracks, call?}`, each track as resolved (`name?`, `node` as an absolute path, `property?`; a named property track keeps its `node` and `property` beside `name`); `stop` ends the watch, or collects one whose window has ended, and answers its timeline; `run` starts one, waits out its window and answers the timeline in one call. The timeline: `{startFrame, frames, gameMs, wallMs, paused?: [[from, to]], stopped?, call?, warning?, tracks: [{name?, node?, property?, first, last, changes, points: [[frame, gameMs, value]], dropped?, cut?, min?, max?, minAt?, maxAt?}]}`, plus the signal and monitor keys below when those tracks are watched. `startFrame` is `Engine.get_process_frames()` at the watch's first frame (`get_physics_frames()` with `unit: "physics"`), so it lines up with `get_game_state`'s `frame` and `frame_control`'s `processFrames`; every `frame` counts from 0 there, paused frames included, and a point's `gameMs` is the game time since then. `frames` and `gameMs` count the unpaused frames sampled and their game time, `wallMs` the real time from the first frame to the window's end. `stopped` is `stop` when a `stop` ended the window early and `deadline` when its deadline did; left out, the window ran full. `call` is the run's `options.call` result, which takes `{node, method, args?}` or a game tool's `{tool, args?}` and answers as `capture_frames`' does.
- **Use:** to learn how values moved over a stretch of play: `run` for one value or several in one call; `start`, drive with any tools, `stop` when the stretch is your own input, a `wait_for` or a step. `wait_for` waits for one condition and says when it held; `capture_frames` keeps images; a watch keeps numbers and values. `tracks {properties: [{node, property, name?, minDelta?}], expressions: [{name, expression, node?, minDelta?}]}`, 1 to 32 tracks together. A property is a name or a path into one (`position:x`, `modulate:a`), read with `get_indexed`, so a non-exported C# field Godot can marshal reads too. An expression is a Godot `Expression` with `wait_for`'s inputs, `root`, `tree`, `Input`, `Engine` and, when the track names a `node`, `node` (also its base instance): `{name: "focus", expression: "root.gui_get_focus_owner()"}`, `{name: "screens", node: "Main/Safe/Screens", expression: "node.get_children()"}`; a Node in a value reads as its path. A track is keyed by its `name`, else by `node:property`; the keys must be unique. `window` is exactly one of `{frames}` (1 to 7200 unpaused frames, physics ticks with `unit: "physics"`) or `{gameMs}` (1 to 120000 ms of game time, the sum of each unpaused frame's scaled delta, so it follows `Engine.time_scale` as the game's own timers do); `start` defaults to `{frames: 600}`, `run` needs one. `options {call, unit, budgetMs}`: `call {node, method, args?}` is called in the watch's first frame, before its first sample, so the window counts from the method's entry (a coroutine is not awaited), and `start`'s and `run`'s replies add `call: {value}`; `unit` is `process` (the default) or `physics`. `minDelta` (above 0, numeric tracks only) keeps a sample only when it moved at least that far from the last one kept (an int or float by its difference, a vector when any component did): `minDelta: 1` on a tween's `position:y`. Between `start` and `stop` any tool runs: input, `wait_for`, `capture_frames`, `get_game_state`, `run_script`, `frame_control`'s `pause`, `step` and `resume`. In `batch_drive`, `start` and `stop` are steps like any other (a later step cannot read an earlier one's result), a `run` step holds the batch for its window inside its 300 s, and a watch the batch leaves running keeps running.
- **Signals:** `tracks.signals: [{node, signal} | {group, signal}]` (at most 16, connecting at most 200 nodes) records every emission as `events: [[frame, gameMs, node, signal, args]]`, in emission order across tracks, plus `eventCounts: {"<node>:<signal>": n}` counting all of them. A group is resolved once at start: a member without the signal is listed in `skipped` (in `start`'s reply and the timeline), and a node joining later is not followed. `start` lists `signals: [{node | group, signal, connected}]`; a node and signal two tracks name is connected and counted once, under the first track, so a later track can show `connected: 0`. A signal is stamped with the frame it fires in, so one emitted beside a value set in frame N's `_process` reads N while the value shows at sample N+1; an emission before the first sample (an `options.call`'s) is frame 0, one in a paused frame is still recorded, and a freed emitter's signals just stop. `events` keeps at most 300, shared fairly across signal tracks, each keeping its earliest, with `eventsDropped` counting the rest; an argument over 200 characters comes back as `{valuePreview, valueLength}`. A C# `[Signal]` is a Godot signal and is watched by its name without the `EventHandler` suffix; a plain C# `event` is not.
- **Monitors:** `tracks.monitors: ["frame_ms", "object/nodes", "<custom id>"]` (at most 16; monitors alone are a watch) reads performance monitors each sampled frame and answers `monitors: [{name, samples, p50, p95, p99, max, maxAt, mean, spikes?, custom?, nonNumeric?, over?}]`, summarised by the game at the end, so a 7200-frame series costs no more on the wire than a short one. `frame_ms` is the wall time between one frame's start and the next's (`Time.get_ticks_usec()`), in ms to 3 decimals: physics, process, draw and the frame cap's wait together, so a 60 fps quiet run idles near 16.7. Its `over: {budget, count, frames}` counts the readings over `options.budgetMs` (0 to 10000; by default 1.5 frames of the game's `max_fps`, else of 60 fps: 25 ms), `frames` being how many readings there were, and its `spikes` are the readings over budget. A built-in monitor is named by Godot's own name for it (`Performance.get_monitor_name`): `object/nodes`, `object/orphan_nodes`, `raster/total_draw_calls`, `raster/total_objects_drawn`, `video/video_mem`, `pipeline/compilations_draw`, `physics_2d/active_objects`, `audio/driver/output_latency`, … (59 in all); its `spikes` are its highest readings, left out when it never changed. A custom monitor is the id the game gave `Performance.add_custom_monitor` (`custom: true`), and a built-in name wins over a custom id of the same name. Percentiles are nearest-rank; `maxAt` is the frame of the first maximum; `spikes` are `[frame, value]`, at most 20, highest first. `start` lists `monitors: [{name, custom?}]`.
- **Edges:** each frame is sampled as it starts, before the nodes' `_process` (at `process_frame`, or `physics_frame` with `unit: "physics"`), so a value set in frame N shows at sample N+1. A frame that finds the game paused is neither sampled nor counted toward the window, and is listed in `paused`; a `frame_control` step's frames are unpaused, so a watch started on a paused game and then stepped samples exactly the stepped frames. `points` are the change points: a sample is kept when it differs from the last one kept (numbers within 1e-6, or by `minDelta`; containers member by member), the first always. A track keeps its first 200 and last 50 change points and counts the ones between in `dropped`; `changes` counts every change point after the first, dropped and cut ones included; `first` is the first point's value (null when nothing was sampled) and `last` the last sample's; `min`, `max`, `minAt` and `maxAt` (frames) cover every sample of a numeric track, per component for a vector (`{x, y}`). A value over 200 characters of JSON, in a point, `first` or `last`, comes back as `{valuePreview, valueLength}`. A timeline over 40000 characters loses points from the middle of its longest tracks first, each track counting its loss in `cut` and keeping at least its first and last point. A property track whose node is freed reads `{"$freed": true}` once and stops. An expression that fails reads `{"$error": "<text>"}` (`its node <path> was freed` once its node is gone), kept again only when the text changes, and goes on sampling, so it recovers when the thing comes back; its failures are not in the call's `errors`. An engine error raised directly by a native method an expression calls (`get_child(0)` before the child exists) is kept out of `errors` too, and the track reads the null the method returns; an error from game code the expression calls (a `push_error`, a script or C# error, an engine check failing inside a game method) still lands, as does any error raised outside the expression; a GDScript game's `push_error` lands only in a build that records call stacks (any debug build, or a release export with `debug/settings/gdscript/always_track_call_stacks`). Refused at start: a missing node, with the not-found text every tool uses; `'<path>' has no property '<name>'.`; `The expression of track '<name>' does not parse: <error>`; a `minDelta` track whose first read is neither a number nor a vector, `minDelta applies to a numeric track (an int, a float or a vector); track '<key>' reads <type>.` (so a `minDelta` expression runs once more at start); `Two tracks are keyed '<key>'; give one of them a different name.`; no track, or more than 32; `window needs exactly one of frames or gameMs.`; `stop takes no tracks, window or options: it ends the watch that runs and returns its timeline.` A `call` refused as `call_method` refuses it, or raising an error, fails the `start` or `run` and ends the watch before it samples. One watch runs per game run: `A watch is already running on this game; end it with watch {action: "stop"} before starting another.`; `The last watch's window has ended and its timeline is not collected yet; collect it with watch {action: "stop"} before starting another.`; while a `run` waits, a `start` or `stop` gets `A watch run is still running on this game; it answers when its window ends, and no other watch can start or stop until then.` A `stop` with nothing to collect says why: `No watch runs: none has started in this game run (restart_project and stop_project drop a watch); start one with watch {action: "start"}.`, `No watch runs: the last one's timeline has already been returned; …` or `No watch runs: the last one was dropped when the connection to the server ended; …`. A `stop` that lands before a starting watch's first frame makes that `start` fail with `The watch ended before its first frame; start it again.` The deadline is the window's allowance (10 s + 100 ms a frame, or `gameMs` + 10 s, at most 600 s): a started watch holds it in real time, lengthened by the time it spends paused (up to 600 s more), and a `run` is released when it passes in load-adjusted time; either way the watch ends with what it has and `stopped: "deadline"`. `restart_project`, `stop_project` and a `detach_project` drop a watch. Expressions and `options.call` run game code, an expression every sampled frame, so write expressions that only read; the tool is annotated destructive for that, and agents keep it in the `read` class. A `run_script` that holds the main thread holds the watch's frames with it. Monitors: `frame_ms` has no reading for the watch's first frame, a paused stretch does not read as one long frame, and an `options.call` that stalls its frame shows in the next reading. A hitch reads as one long frame (a 300 ms stall reads about 301-303) followed by one near 0, since Godot skips the next frame's wait to catch up. `raster/*` counts 2D draws as well as 3D, and `memory/static` moves while a watch records because the watch's own buffers grow. `pipeline/compilations_*` are cumulative and stay 0 under the Compatibility renderer. A custom monitor whose first read is not a number is refused at start; a later non-number, or an id the game removed, counts in `nonNumeric`. Refused at start: `'time/fps' is set once a second, so read per frame it repeats one value and hides which frame was slow; watch 'frame_ms' instead.` (and `time/process`, `time/physics_process`, `time/navigation_process`); `frame_ms measures process frames; drop options.unit "physics" or the frame_ms monitor.`; `options.budgetMs applies to the frame_ms monitor; add "frame_ms" to tracks.monitors or drop budgetMs.`; an unknown name, `No monitor '<name>': not one of Godot's 59 built-in monitors (such as object/nodes or raster/total_draw_calls), not frame_ms, and no custom monitor has that id; a game registers one with Performance.add_custom_monitor.`; more than 16 monitors, or one named twice. `warning` says when a reading misleads: frame_ms in a Movie Maker recording, however it was started (it measures rendering speed, not what a player sees), a `raster/*` monitor while no frame was drawn (minimized, headless or low-processor mode), and sampling that averaged over 2 ms a frame, which slows the frames it watches.

### `wait_for`

- **Does:** waits until `condition` holds, checked each frame, exactly one of `{node, exists}`, `{node, property, equals}`, `{node, signal}`, `{expression}`, `{uiChanged: true}`, `{gameMs}` or `{frames}`: `{met, elapsedMs, frames, value}` (`args` for a signal), or on timeout `{met: false, ..., last}`.
- **Use:** after an input, to wait for its effect instead of sleeping; `timeoutMs` 0 to 120000, default 10000, load-adjusted: under load it waits longer in wall time. So a `timeoutMs` is never a pause: to hold for a span of the game's own time (a shot 0.5 s into an effect), wait `{gameMs: N}` (1 to 120000 ms of process delta over unpaused frames, so it follows `time_scale` and load does not stretch it) or `{frames: N}` (1 to 7200 unpaused process frames), each alone, counted from the first frame after the request; `value` is the game ms (whole) or frames reached, up to one frame past N. Left out, their `timeoutMs` is N + 10000 for `gameMs` and 10 s + 100 ms a frame for `frames`, at most 600000. A `gameMs`, `frames`, `exists`, `property` or `expression` wait takes `options.call {node, method, args?}` or `{tool, args?}`, as `capture_frames` does: the method or game tool is called in the frame the checks start (the next process frame), so a `gameMs` or `frames` count runs from the call's entry, and another wait's first check follows the call in that frame, its `frames` and `elapsedMs` counted from that check (a wait met there reports `frames: 0`). The result adds `call` as `capture_frames`' does; a refused or erroring call fails the wait. A check-once wait (`timeoutMs: 0`) with a call waits for the next frame, calls, then checks once. A `signal` or `uiChanged` wait refuses `options.call` (`options.call is taken only by a gameMs, frames, exists, property or expression wait; this condition is {kind}.`), and `batch_drive`'s wait assertion has none: put a `call_method` step before it. In a recording (`run_project` `options.record`) it counts clip time instead, 60 movie frames a second, however slowly the game runs, so a timed-out `expression: "false"` wait holds a still of exactly that length in the clip, and the result adds `clipMs`, the clip time waited (`elapsedMs` stays real time). `{uiChanged: true}` waits for a UI change nobody can name in advance: it compares the visible Controls (as `get_ui_elements` lists them), the focus owner and the top popup with the baseline the bridge snapshots when the first input gesture since launch, or since the last met `uiChanged` wait, starts. Later gestures keep that baseline, so a press and a separate release, or a batch's several inputs, all count; a met wait uses it up and a timeout keeps it. Its `value` is `{appeared, disappeared, appearedCount, disappearedCount}` (node paths, at most 20 in each list, the counts full), plus `focus` and `popup` `{before, after}` when those changed; on a timeout `last` is null. `property` takes subproperty paths (`position:x`); `equals` compares as `run_script` returns values, numbers within 1e-6. An `expression` sees `node`, `root`, `tree`, `Input` and `Engine`. `options.screenshot: true` captures the frame the condition was met on, as `take_screenshot` does, adding `screenshot {path, width, height, previewPath, previewWidth, previewHeight}` and a preview image at most 480 px wide: for a scene that changes faster than a following `take_screenshot` can catch.
- **Act in the met frame:** `options.then {call?: {node, method, args?} | {tool, args?}, timeScale?}`, taken by every condition and by a check-once wait, runs once in the frame the condition is first found true (the met frame): `call` first, then `timeScale` (above 0, at most 100), which scales the next frame on. A slow-motion shot of a moment: `wait_for {condition: {expression: "…"}, options: {then: {timeScale: 0.2}}}`, then `capture_frames`, or give `capture_frames` an `options.start` that waits for the condition and counts its points from the met frame. The result adds `then: {frame, call?: {value}, timeScale?}`, `frame` being `Engine.get_process_frames()` when it ran. A plain wait runs it at that frame's start, before the nodes process (a check met at once runs it inside the request); with `options.screenshot` it runs after the met frame is drawn and grabbed, but a check-once wait runs it before its capture, which can then show its effect; a signal wait runs it in the frame the wait notices the emission. A refused or erroring `then.call` fails the wait with no screenshot: `The condition was met after 12 frames (frame 4810), but then.call failed, so timeScale was not set: …`. A timeout runs nothing. A recording's 60 fps clip does not follow `timeScale`. `batch_drive`'s wait assertion takes no `then` and no `edge`: use a `wait_for` tool step.
- **Wait for a rise:** `options.edge: true`, with an `exists`, `property` or `expression` wait, is met only on a check that finds the condition true after a check that found it false. A first check that already finds it true is not met, so a condition already true waits for its next rise (with `options.call`, the baseline check runs in the call's frame before the call, so an effect the call makes at once is met as a rise), and one true for the whole wait times out with `met: false` and `last` the true value. A check whose expression fails to run does not count as false. Use it to start a `then` on the event itself, not on a state that held before the wait: a `visibility_changed` signal wait is no substitute, since it fires on hide too. Any other condition is refused (`options.edge applies to exists, property and expression waits; this condition is {kind}.`), and so is `timeoutMs: 0` (`timeoutMs 0 checks once, which an edge wait cannot meet; give it a timeout.`).
- **Edges:** a timeout is a result (`met: false`), not an error. While the game is paused only a signal wait or a check-once wait (`timeoutMs: 0`) is accepted; a check-once wait is refused for a signal, `gameMs` or `frames` wait, and a pause during a `gameMs` or `frames` wait stops its count, so it runs to its timeout with `last` the progress. `equals: null` is not supported: use an expression (`node.target == null`). With `options.screenshot`, the condition is checked inside each frame's draw, so the image shows the state the check saw; a timed-out wait captures nothing, a check-once or signal wait captures the draw of the frame running when it is met, which in a running game can already show nodes that processed after the check (pause first for an exact image), and a frame not drawn (a minimized window, low-processor mode) answers a `warning` and no image. A property the node lacks fails the call; an expression that does not parse fails it, as does one with text after a complete expression, which Godot's `Expression` would otherwise ignore (`a if b else c` would read as `a`; `x is Node` as `x`): `the expression does not parse: text follows a complete expression, and Expression would ignore it`. That refusal, and one whose source uses GDScript syntax `Expression` lacks (`func`, `if`, `else`, `is`, `as`, `return`, `var`, `await`, `not in`), ends with `Godot's Expression is not GDScript: …`, listing what it has. An expression that fails while it runs (an index past an empty array) counts as not met for that check, and its error is in `errors`; a result that follows failed checks adds `failedChecks {count, error}` (the last failure's text), so a `met: true` after them shows the expression did not hold all along. `Expression` evaluates both sides of `and` and `or`, so `a.size() > 0 and a[0] == x` fails, rather than short-circuits, on an empty `a`. `uiChanged` takes no `node` and is refused when no gesture has taken a baseline since launch or since the last met `uiChanged` wait; a gesture the bridge refuses (an unknown element or key) still takes one. Tooltips, drag previews and the bridge's own nodes never count as a change; the change may already have landed during the gesture's settle frames, so the wait can be met at frame 0.

## Inspect and change the running game

### `get_scene_tree`

- **Does:** lists the live nodes depth first: path, name, class, script, groups, childCount.
- **Use:** `root` (a node to list from), `className` (with subclasses), `group`, `options {maxDepth, offset, limit}`.
- **Edges:** the bridge's own nodes are left out. `className` and `group` filter the listing, not the walk.

### `inspect_node`

- **Does:** reads a live node: `{path, class, script, properties}`, by default its script variables and the inspector's properties. For a C# script the default holds only its `[Export]` members: the editor build Godot runs leaves the others out of the property list.
- **Use:** `node`, and `properties` to read exactly those names (a name the node lacks fails). A named non-exported C# field is read too, as `set_property`, `wait_for {property}` and `watch`'s property tracks reach it; `cs_members` lists them.
- **Edges:** values over 2000 characters come back as `{valuePreview, valueLength}`.

### `set_property`

- **Does:** sets one property of a live node, converting the JSON `value` by the property's declared type, and reads it back: `{path, property, before, after}`.
- **Use:** putting the game into a state to test (`{x, y}` for a Vector2, `"#rrggbb"` or `{r, g, b, a}` for a Color).
- **Edges:** fails, putting the old value back, when the read-back differs (a read-only property, a clamping setter). Typed arrays and dictionaries (`Array[int]`, `Dictionary[String, int]`), exported or not, take a JSON array or object; one whose elements, keys or values are Objects or Resources (`Array[Node2D]`, `Array[Texture2D]`) is refused, and the error says why.

### `call_method`

- **Does:** calls `method` on a live `node` with `args` converted by the parameters' declared types, awaiting a coroutine: `{path, method, value}`.
- **Use:** triggering game logic directly (spawn, damage, load a level); C# methods, `internal` ones included, are reached. `options {timeoutMs}` (1 to 120000, default 10000, load-adjusted).
- **Edges:** fails when the method is missing, the argument count does not fit, an argument does not convert (an array of Objects says why), or Godot refuses the call. A GDScript error inside it ends it with a null `value` and comes back in `errors`; the call itself succeeds, so read `errors`. Past `timeoutMs` the call fails, `Engine.time_scale` and `SceneTree.paused` go back to their values at the call's start (the error names what it restored), and the method keeps running on its node: only `restart_project` stops it.

### `cs_members`

- **Does:** lists the C# members of a `target`, exactly one of `{node}` (a path, bare name or `%UniqueName`; the node must have a C# script), `{type}` (a full name with its namespace, e.g. `CsProbe.Tally`: statics and constructors) or `{handle}`: `{type, members: [{kind, name, signature, static}], total, offset, next?}`. Kinds are `constructor`, `method`, `property`, `field`, `event`; every overload is its own entry, spelled as C# declares it (`internal string Hit(int amount)`). `options {name, nonPublic, offset, limit}`: `name` a case-insensitive part of the member name, `nonPublic` true by default, paged 100 at a time (at most 500), sorted by name then signature.
- **Use:** before calling into a C# game object whose members Godot's own call cannot reach or show: private fields, overloads, generics, static classes. Reads only: no getter or constructor runs.
- **Edges:** lists the game's own types down to, not including, the first Godot class (`describe_class` lists Godot's API); accessors, backing fields, record plumbing and the members Godot's source generator adds are left out. A node without a C# script is refused, naming its Godot class; so are the bridge's own nodes, a type no loaded assembly has, and a handle from an earlier run. The first C# call of a game loads the helper into it (about 2 s cold); a project with no C# assembly, or an unbuilt one, is refused before the game is asked.

### `cs_get`

- **Does:** reads a C# property or field of a `target` (as `cs_members`: `{node}`, `{type}` or `{handle}`), private and internal ones included: `{value, type}`, `type` the value's runtime full name (the member's declared type for a null). `member` is a name or a dotted path through properties, fields, list indexes and dictionary keys (`Pending.Options[0]`, `Scores["key"]`); a `{type}` target starts at a static member. `options {maxDepth, keep}`: nested objects written 8 levels deep by default (1 to 32); `keep` also returns a `handle` usable as `{handle}` in a later C# call.
- **Use:** for game state Godot's own `get` returns null for: private fields, records, `List<T>`, statics of a plain C# class.
- **Edges:** a getter runs game code. A Godot object comes back as `{"$node": path}`, `{"$object": class, id}` off the tree, or `"<freed object>"`; a value over 20000 characters as `{valuePreview, valueLength}`. `keep` on a null returns no handle and a `warning`; on a value type, a handle to a copy, with a `warning` that a set through it does not reach the source. Fails on a method name, on an instance member named from a `{type}`, on a `{handle}` to a freed Godot object, and when a getter throws, with the exception's type, message and stack.

### `cs_set`

- **Does:** sets a C# property or field of a `target` and reads it back: `{member, before, after}`. `member` is a name or dotted path whose last segment is a property, field, list index or dictionary key (`Pending.Count`, `Items[2]`, `Scores["key"]`); `value` is JSON converted by the member's type: a record or class from an object, an enum by name or number, a list from an array, an interface or abstract member from `{"$handle": h}` or `{"$node": path}`.
- **Use:** to put a C# game object into a state for a test when no method gets it there.
- **Edges:** writes what reflection allows: non-public and `init` setters and readonly instance fields; refuses a property with no setter (or no getter, since it cannot be read back), a `const`, a `static readonly` field, and a path through a struct, whose set would change a copy (set the struct whole). A list index or dictionary key must already exist. When the member reads something else after the set (a setter that clamps), the old value is put back and the call fails with both (each cut at 2000 characters); a read-back that throws puts the old value back too, and a put-back that fails says what the member now reads. `before` and `after` over 20000 characters come back as `{valuePreview, valueLength}`. A setter that throws fails with the exception's type, message and stack.

### `cs_call`

- **Does:** calls a C# method or constructor of a `target` (as `cs_members`), private and internal ones included: `{value, type}`, `type` the value's runtime full name, `System.Void` for a void. A `{node}` or `{handle}` calls an instance method, a `{type}` a static one, and `member: ".ctor"` on a `{type}` constructs one. `args` is a JSON array in parameter order, each converted as `cs_set` converts a value; a `params` parameter takes its array as one value, an `out` takes null, and what `ref` and `out` parameters hold after the call comes back as `outs {name: value}`. `options {signature, typeArgs, keep, timeoutMs, maxDepth}`.
- **Use:** for C# game methods `call_method` cannot reach: overloads sharing a name and count (`Hit(int)`/`Hit(float)`), generics (`typeArgs: ["int"]` or full names), records and `List<T>` arguments, interface parameters (`{"$handle": h}`), statics of plain C# classes, async methods.
- **Edges:** when several overloads fit, the call fails listing each with its ready-to-paste `options.signature` array (in `cs_members`' spelling). A returned `Task` or `ValueTask` is awaited up to `timeoutMs` (10000 ms by default, at most 120000, load-adjusted); past it the call fails and the `Task` keeps running in the game. `keep` returns a handle, with `cs_get`'s warnings; a `Node` made by `.ctor` is freed after the call unless kept, and a kept one is outside the tree, with a warning to free or add it. A thrown exception fails with its type, message and stack. Godot's own methods are refused, pointing to `call_method`; a property or field, pointing to `cs_get`; pointer and `Span`-like parameters are refused. Values and outs over 20000 characters come back as `{valuePreview, valueLength}`.

### `list_game_tools`

- **Does:** lists the game's own C# methods marked `[GodotMcpTool("what it does")]`, an attribute the game declares itself (any namespace; matched by the name `GodotMcpToolAttribute`, with optional `Name`, `When` and `ReadOnly` properties; parameter descriptions from `[System.ComponentModel.Description]`): `{tools: [{name, description, when?, readOnly, on, args?, returns, available, reason?}], total, offset, next?, build?, hint?}`, sorted by name. `on` is the owner a call would run on: an autoload's name (`Net`), the current scene root's path (`/root/HandScratch`), `static <Type>` (the full name when two static owners share a short one), or null. `args` is a JSON Schema object of the named arguments, each property with `x-csharp` (the C# type as `cs_members` spells it), `description` and `default`. `options {name, offset, limit}`: `name` a case-insensitive substring, `offset` from 0, `limit` 1 to 500 (default 100).
- **Use:** before reading a game's docs for its cheats and debug commands; a marked tool is the game's own way to jump to a room, set a value or play a scratch step, where `cs_call` would need the method's internals; `call_game_tool` then calls one by its name.
- **Edges:** owners and availability are read from the live tree at each call, so a tool on a scene root is available only while that scene is current. A tool is listed `available: false` with its `reason` when its type is neither an autoload's, the current scene root's nor static (its `args` kept), when a parameter cannot be passed by name (`out`, `ref`, pointers, delegates, a generic method; no `args`), when two marked methods share a name, or when its mark has no description string. `build: "stale"` says the game runs an older build than the one on disk: the list is what the running game loaded, and `restart_project` runs the new one. A game that marks nothing gets an empty list and a `hint` on declaring the attribute; a `[Conditional("DEBUG")]` attribute class leaves the marks out of a Release build. A GDScript project is refused, pointing at `call_method`; a project with no built C# assembly is refused as the `cs_*` tools refuse it.

### `call_game_tool`

- **Does:** calls one of the game's own tools, a C# method it marks `[GodotMcpTool]`, by its name as `list_game_tools` lists it, on the owner the listing names: `{name, args?, options?: {timeoutMs, maxDepth}, session?}` → `{tool, value, type, build?, errors?}`. `args` is an object keyed by parameter name (`{"enemy": true, "index": 0, "hp": 6}`), each value converted as `cs_set` converts one (`{"$node": path}` for a node, an enum by name or number); a parameter with a default may be left out. `type` is the value's runtime full name, `System.Void` for a void; a returned node reads as `{"$node": path}`. `timeoutMs` 1 to 120000 (10000 by default, load-adjusted), `maxDepth` 1 to 32 (8 by default).
- **Use:** for a game's cheats and debug commands once `list_game_tools` has shown them: `call_game_tool {name: "SetHp", args: {enemy: true, index: 0, hp: 6}}` in place of a positional `cs_call` whose argument meanings live in the game's source. It runs in `batch_drive` like any tool, so a cheat, a `wait_for {frames}` and a read go in one call.
- **Edges:** names match exactly (case-sensitive), and a mark's `Name` replaces the method's. Refused before any game code runs: a name no mark gives (`cs_call` reaches an unmarked member), a tool the listing shows unavailable (with its `reason` word for word), an unknown, missing or wrongly typed argument (`SetHp has no parameter 'hitpoints'; it takes enemy, index, hp.`, with a case hint), `args` that is not an object or names a key twice. A returned `Task` is awaited up to `timeoutMs`; past it the call fails and the `Task` keeps running in the game. A thrown exception fails with its type, message and stack. `build: "stale"` says the game runs an older build than the one on disk; the call still runs the code the game loaded, and `restart_project` runs the new build. A value over 20000 characters comes back as `{valuePreview, valueLength}`. A GDScript project is refused, pointing at `call_method`.

### `run_csharp`

- **Does:** compiles `code`, a C# method body (statements, or one expression whose value is returned), in the server and runs it in the game on the main thread: `{value, type}` as `cs_call` answers, `type` the value's runtime full name, null for a null value. `await` works in the body, and an unfinished result is awaited up to `timeoutMs` (load-adjusted). In scope, unqualified: `Tree` (the `SceneTree`), `Root`, `ToSignal(source, signal)` as a node's script has it (`await ToSignal(Tree, SceneTree.SignalName.ProcessFrame)` waits one frame, in a paused game too; it takes no token, so a signal that never fires holds the snippet past its timeout), `Node(path)` and `Node<T>(path)`, `Handle(id)` and `Handle<T>(id)`, `Get(target, path)` and `Get<T>`, `Set(target, path, value)`, `Call(target, method, args...)` (private and internal members included; `Type` forms of `Get`/`Set`/`Call` for statics), `Keep(value)`, which answers a handle id for a later `{handle}` target, and `Cancellation`, the `CancellationToken` the call's timeout cancels. Usings: `System`, `System.Linq`, `System.Collections.Generic`, `System.Threading.Tasks`, `Godot` and the game's root namespace, plus `options.usings`. `options {usings, timeoutMs, keep, maxDepth}`.
- **Use:** what the `cs_*` tools cannot say in one call: building a record and passing it to a method (`t.Bind(new Update(...))`), a loop, several calls whose results feed each other, awaiting a game `Task`. Public and internal members of the game's assemblies (and GodotSharp's) are named directly, as code inside those assemblies would (`Node<CsTargets>("CsTargets").Hit(2)` with an `internal Hit`); a private one only through `Call`/`Get`/`Set`, and a `CS0122` compile error says so. .NET's own non-public members stay out of reach: naming one is a `CS0122` before the game is asked.
- **Edges:** a snippet that does not compile is refused with no call to the game: `run_csharp failed: the snippet does not compile:` then one `snippet(line,col): error ID: message` line per error, at most 20. A game running an older build of any of its own dlls, or of the C# helper, than the one on disk is refused, naming `restart_project` (Godot's `GodotSharp` is not checked: the game loads the engine's copy). A snippet declares no types (lambdas, local functions and anonymous types work). Inside the snippet `Node` names the method, so a static of Godot's type is `Godot.Node.X`. `Call` picks an overload by the arguments' runtime types with no numeric widening (`1` does not reach `Hit(float)`: pass `1f`), and refuses a generic method (use `cs_call` with `typeArgs`) and `out`/`ref` parameters. The snippet compiles against the .NET runtime the game runs (the one its target framework loads: .NET 8 or 10 on Godot 4.7), so an API newer than the game's is a compile error. A thrown exception fails with its type, message and a stack naming `snippet:line N`. Past `timeoutMs` the call fails as `cs_call`'s does and `Cancellation` is cancelled, so a snippet that passes it to its awaits or checks it in its loops stops; one that ignores it keeps running, and a loop on the main thread that never yields cannot see the cancel; what the snippet does after the timeout is not reported. `keep` and the 20000-character cut as `cs_call`'s; each run loads into its own collectible context, unloaded once its result is written.

### `get_game_state`

- **Does:** reads the game's own state in one frame: every node in the `mcp_state` group, in tree order, with what its `_mcp_state()` returns: `{frame, nodes: [{path, class, state} | {path, class, error}], total, omitted?: {count, paths}, hint?, errors?}`. `frame` is the engine's process frame count at the read; `total` counts every marked node (under `node` when given); `omitted` counts the nodes left out past `maxNodes` or the 40000-character budget of the list and names the first 20. A node's JSON keys arrive sorted. `node` reads only the marked nodes at or under it. `options {keys, maxNodes, maxDepth}`: `keys` keeps only those keys or dotted paths of each state (`seats[0].hp`), returned flat under the key as given, a missing one left out and one cut by `maxDepth` given as its depth marker; `maxNodes` 1 to 500 (50 by default), counted in tree order before any node is read; `maxDepth` 1 to 8 (4 by default), a deeper Dictionary or Array written as `"<depth limit: Dictionary>"`; past 5000 values written for one node the rest read `"<size limit>"`, so shared references cannot multiply; `keep` (false by default) also holds the read in the session for `diff_snapshots` and adds `stateId` to the result.
- **Use:** in place of a screenshot or a sampling script, when a game opts in: a GDScript node joins the `mcp_state` group and defines `func _mcp_state() -> Dictionary` returning the few values a player would read off the screen; a C# node joins the group and defines `_McpState()`, an instance method with no parameters, of any accessibility, returning any value (a record, an anonymous type, a `Dictionary<string, object?>`), found on its type or a base up to the GodotSharp types and called by the C# helper in the same frame as the GDScript nodes, its value written as `cs_get` writes one (a Godot object as `{"$node": path}`, past `maxDepth` `"<depth limit: Type>"`, past 5000 values `"<size limit>"`). A C# node with no `_McpState` but a Godot-visible `_mcp_state` returning a Dictionary is read through it; one with both reads `_McpState` and says so in `warning`. The helper loads only when a marked C# node is within `maxNodes`. It runs in `batch_drive` and inside `frame_control` steps.
- **Edges:** state methods are game code and run at every read, so a side effect in one repeats. A node's `error` says why it has no state: `in the mcp_state group but has no _mcp_state method`, `_mcp_state raised: <the error>` (also in `errors`), `_mcp_state returned a coroutine, which is not awaited`, `_mcp_state raised an error the log no longer holds` (past the error log's 200 entries), a GDScript node with only the C# name `_McpState`; for a C# node, `<Full.Type> has no _McpState() (an instance method with no parameters, any accessibility)`, `<Exception>: <message>` when the method (or writing its value) throws, `<Full.Type>._McpState returns a Task<int>; a state method must return its value, not a task` (never awaited), `<Type> is a C# script; its _McpState is read by the C# helper, which cannot run: <why>` (several csproj files, an unbuilt assembly, a helper that failed to load or refused), or `…, which this project has no build of`. One C# node's failure never blanks the others. A `null` return reads as `state: null`. A state over 4000 characters comes back as `{valuePreview, valueLength}`. The bridge's own nodes are never read. A marked node an earlier node's state method freed is skipped, still counted in `total`. A whole-tree read that finds no marked node returns an empty list and a `hint` on opting in; `snapshot_subtree` and `get_ui_elements` read an unmarked game. A kept read is held flattened, one value per leaf of each node's state keyed by its dotted path (`seats[1].hp`; list elements `[i]`, a state that is itself a list from `[0]`), with `$` for a whole state that is a scalar, null or empty, an empty nested Dictionary or Array as one leaf `{}` or `[]`, cut marks and a preview's `valuePreview`/`valueLength` as leaves, and an errored node as the one leaf `error`; nodes in `omitted` are not held. A member name holding `.` or `[` reads like a path. It shares `snapshot_subtree`'s 16 held snapshots and id sequence.

### `snapshot_subtree`

- **Does:** captures a live subtree for a later `diff_snapshots`: every node under `node` (default the current scene's root), keyed by its path from that node (`.` for itself), with the properties the inspector shows and its groups (sorted, internal `_` ones left out). Returns `{snapshotId, node, nodeCount}`, not the data.
- **Use:** before an action whose effects you cannot list in advance. `options {properties, ignore, maxNodes}`: `properties` narrows each node to those names (read even when the inspector hides them; `groups` only when named), `ignore` drops names, `maxNodes` (default 2000) refuses a bigger subtree with its count.
- **Edges:** snapshots are of the running game only, held per session, the 16 most recently used, `get_game_state`'s kept reads among them; ids (`s1`, `s2`, …) never repeat in a session, and every snapshot is dropped when the run stops, exits or restarts, or when an attached game's connection ends. Inside one `batch_drive`, a later step cannot read an earlier step's `snapshotId`, since arguments are fixed before the batch runs.

### `diff_snapshots`

- **Does:** compares two held snapshots of one kind, two `snapshot_subtree` captures or two `get_game_state` reads kept with `keep`: `{added, removed, changed: [{node, property, before, after}], addedCount, removedCount, changedCount}`, each list at most 200 entries with full counts. A subtree's node paths are relative to its root; a state read's are absolute, and its properties are the leaves of each node's state (`seats[1].hp`, `$`, `error`), so one hit point changing is one `changed` entry.
- **Use:** `beforeId` from `snapshot_subtree`'s `snapshotId` or `get_game_state`'s `stateId`; without `afterId` the live game is taken again now as the before snapshot was: a subtree captured with its root and options, or a state read repeated with its `node`, `keys`, `maxNodes` and `maxDepth`, through the C# helper when the first read was. So `get_game_state {options: {keep: true}}`, act, `diff_snapshots {beforeId}` shows what the action changed in the game's own state. Numbers compare within 1e-6, so a float that only round-trips differently is not a change.
- **Edges:** annotated destructive, since the live re-read of a state read runs the game's state methods (game code); agents keep it in the `read` class. A subtree snapshot and a state read are refused together: `Snapshot s1 is a subtree snapshot and s2 is a state read (get_game_state); diff two of the same kind.` Elements of a list are keyed by index, so an element inserted at the head diffs as every later element changed; key a list by id in the state method where that matters. A property only one side has is a change whose missing side's key (`before` or `after`) is left out, not null. An id that is not held (evicted, or from a run that stopped or restarted, or an attached game that has gone) is refused with a hint to take a new one. Two ids are not checked to share a root: nodes match by relative path.

### `run_script`

- **Does:** runs GDScript inside the game; the `script` must `extends RefCounted` and define `func execute(scene_tree: SceneTree) -> Variant` (it may await). Returns `{value}` as JSON.
- **Use:** anything `inspect_node`, `set_property` and `call_method` cannot express: loops, several nodes at once, engine singletons. `timeoutMs` default 30000, load-adjusted.
- **Edges:** fails on a compile error, or when `execute` returns null and an error is located in the script itself; a null with errors elsewhere still succeeds. GDScript cannot reach a C# member Godot does not marshal (a `List<T>`, a plain C# class, a private member): in a C# project such a failure (Godot's `Invalid access to property or key`, `Invalid assignment of property or key` or `Invalid call. Nonexistent function`) ends with a line pointing to `cs_get`, `cs_call` and `run_csharp`, which reach it. A value over 20000 characters comes back as `{valuePreview, valueLength}`. Past `timeoutMs` the script is stopped and the call fails: `execute` never resumes, and `Engine.time_scale` and `SceneTree.paused` go back to their values at the call's start (the error names what it restored), so a timed-out script cannot disturb the next call. A coroutine it awaited on another object, such as a node's own method, keeps running. A script that finishes keeps its changes.

## Errors and debug output

### `get_errors`

- **Does:** the session's logged errors and warnings, oldest first: `{errors: [{seq, type, message, file, line, function, stack}], next, dropped}`.
- **Use:** to see warnings (tool results carry errors only), or what happened between calls. Pass `since` = the previous call's `next` to read only newer entries (`next` equals `since` when nothing new arrived); `limit` 1 to 500, default 50.
- **Edges:** the server keeps the last 500; `dropped` counts those lost. See also `get_debug_output` above.

## Replay with checks

### `batch_drive`

- **Does:** plays 1 to 100 `steps` against a running game in one call and stops at the first failure: `{passed, steps: [{index, tool | assert, ok, result | error}], failedAt?}`.
- **Use:** a regression check or a long repeatable sequence. A step is `{tool, args}` (any runtime tool of this server but `batch_drive` and `save_screenshot`, with its own arguments) or an assertion `{assert, ...}`: `property {node, property, equals, timeoutMs?}`, `expression {expression, timeoutMs?}`, `wait {any wait_for condition, gameMs and frames included, timeoutMs?}` (wait_for's own default timeout), `no_errors {}`, `screenshot {name, tolerance?, maxChangedRatio?}`. Any step may carry `session`; the batch's `session` is the default.
- **Edges:** `property` and `expression` default to `timeoutMs: 0` (checked once, now); `wait` defaults to 10000. `no_errors` covers errors since the batch started or the previous `no_errors`. `take_screenshot` and `compare_screenshot` steps are forced to `path_only` and images dropped. Not batchable: the lifecycle tools, `preview_scene`, `save_screenshot` (it writes a project file, which `batch_drive`'s class does not grant) and the headless tools. The whole batch stops after 300 s of load-adjusted time.

## Screenshot baselines

### `save_screenshot_baseline`

- **Does:** stores the next drawn frame as a named baseline under `.godot/godot-mcp/baselines/`: `{name, baselinePath, width, height, crop}`.
- **Use:** once the game shows the state you want to guard; `name` (1 to 64 letters, digits, `.`, `_`, `-`, starting with a letter or digit), `crop`, `options {overwrite}`.
- **Edges:** an existing name is refused without `options.overwrite`. Crop to the region under test: a clock or particle elsewhere on screen makes every comparison fail. Pause an animating game (`frame_control`) before saving and again before comparing, or the animation counts as changed pixels; a shader driven by `TIME` keeps moving while paused (`take_screenshot`'s "A before/after pair").

### `compare_screenshot`

- **Does:** captures the next frame with the baseline's crop and counts pixels whose channel differs by more than `tolerance` (0 to 255, default 2): `{changedPixels, totalPixels, changedRatio, bbox, match, diffPath?, ...}` and a diff image (changed pixels red).
- **Use:** `name`; `options {maxChangedRatio, responseMode, previewMaxWidth}`, `maxChangedRatio` default 0.
- **Edges:** a mismatch is a result, not an error. A missing baseline fails, and so does a capture of another size (a different `--resolution` or window size from when it was saved). Pause the game (`frame_control`) first for a stable frame.

## Recording

### `record_mark`

- **Does:** marks the `start` or `stop` of a clip in a session launched with `options.record`, at the movie frame reached: `{mark, frame, seconds}`.
- **Use:** bracket the moment worth keeping; when the run ends (`stop_project`, the game quitting, `restart_project`) each start-stop pair is cut to its own file with ffmpeg, and a start left open clips to the end.
- **Edges:** marks alternate start, stop. A recording runs at a fixed 60 fps, so game time advances 1/60 s a frame whatever the wall clock does, and the game runs uncapped. `wait_for`'s `timeoutMs` and the gesture durations (`drag`'s `durationMs`, `hover`'s tooltip wait, a gamepad sweep) count clip time, 60 frames a second, and a wait's result adds `clipMs`; a recorded wait is released after 10 s + 100 ms a frame of load-adjusted time, so a long wait in a slow game can meet `batch_drive`'s 300 s deadline. A game started with `--write-movie` by hand and then attached keeps wall-clock durations. Capped at 10 minutes of frames; not with `--headless`. Without ffmpeg the full movie is kept and the result reports an error. If the server exits, the movie is lost.

## Headless scene editing

These run a headless Godot on the project's files with no game started, beside any live session on the folder. The write tools always run the prep, open the scene as the editor does and save it with its uids kept; each edit is all or nothing. The scene edit tools write `.tscn` only; a binary `.scn` can be read but not edited. A node inside an instanced scene is refused (edit that scene's own file), except where a tool below says an editable instance or an instance's root is allowed.

On a GDScript-only project the headless Godot stays up between calls (a warm host, one per folder and server), so consecutive calls skip Godot's start: its first call on a folder costs a start, the next ones a few milliseconds. Any change to the folder's files the host did not make (your own edit, the editor's, another server's), an import, a crash or a ceiling restarts it on the next call, which then costs a start again; nothing is retried. While it lives it holds the folder as its working directory, so renaming or deleting the folder (removing a worktree) is refused until it stops: run `stop_project {projectPath}` on the folder first, which waits for a headless call running on it. A host stops by itself after 5 minutes (wall time) with no call; at most 4 run per server, a fifth folder stopping the one idle longest (a busy one is never stopped); it runs at 30 fps while idle and at the engine's headless floor (about 145 iterations a second) for a second after each call; and a call after which a `res://` resource it named stays cached restarts it. `list_sessions`' `headlessHosts` lists them. A C# project starts a fresh Godot for every call. The host's log is `.godot/godot-mcp/headless-host-<server pid>.log`; a C# project's is `.godot/godot-mcp/headless.log`.

### `describe_class`

- **Does:** lists a class's properties, methods with typed arguments, signals, constants and enums: `{className, inherits, inheritsChain, canInstantiate, isScript, scriptPath?, language?, properties: [{name, type, default?}], methods: [{name, args: [{name, type, default?}], returnType, isVirtual, isStatic}], signals: [{name, args: [{name, type}]}], constants, enums, methodCount, offset, limit, warning?}`.
- **Use:** before `call_method`, `set_property` or a headless edit on a class you do not know, engine (`Button`) or the project's own `class_name`. `projectPath`, `className`, `options {inherited, offset, limit}`: an engine class lists its own members unless `inherited`; methods are sorted by name and paged (`limit` 1 to 500, default 100, `methodCount` the total). When a game runs on the project (or `session` names one) that game answers; otherwise it is read headless.
- **Edges:** an unknown name is refused with up to 5 close names (`Did you mean: …`). Properties the editor neither shows nor stores (`Node.name`, `Node2D.global_position`) are listed without `default`, since Godot keeps none for them. A script class's lists include its base scripts' members; `inherited` adds the native base's. A C# script class whose lists come back empty carries a `warning` that the build may be red or stale. Engine enum members appear under `enums`, not `constants`. The editor binary's class list includes editor-only classes, so a suggestion may name one.

### `validate`

- **Does:** loads scripts, scenes and resources without running the game and reports errors: `{valid, checked, results, engineErrors?, csharp?, prep}`; `results` lists only files with errors.
- **Use:** after edits, before a launch. `targets` (1 to 50 files), or none for every git-versioned `.gd`, `.tscn` and `.tres` (at most 500); `options {prepare}`.
- **Edges:** Godot's parser reports only the first parse error in a file: fix it and validate again. A failed C# build comes back as `csharp {build: "failed", errors}` and makes `valid` false while GDScript is still checked. Autoloads' `_init` still runs. Every C# script a target reaches, through instanced scenes and resources however deep, is checked for its class.
- **C# targets:** a `.cs` target is checked through the build and through the versioned `.tscn`/`.tres` files whose `ext_resource` names it (at most 20, checked as targets): `csharp.files` gives each `.cs` target's `{path, errors, warnings, from, scenes}`, each diagnostic `{file, line, column, code, message, severity}`, and `csharp.otherErrors` the errors in the assembly's other files (each list at most 20, the rest counted). Errors make `valid` false; warnings never do. With nothing stale no build runs, so the diagnostics come from the last prep build (`from: "last build at <UTC>"`); a project with no saved build is rebuilt once (`--no-incremental`). A `.cs` target is refused in a project with no `.csproj` or several, and when it is outside the csproj's `Compile` items.

### `get_scene_file_tree`

- **Does:** lists a scene file's nodes without running any code, instanced scenes expanded and an inherited scene's base merged: path (from the root, `.`), name, type, script, instance, groups, childCount.
- **Use:** before a scene edit, to learn node paths. `scenePath`, `root`, `options {maxDepth, offset, limit, prepare}`.

### `create_scene`

- **Does:** writes a new `.tscn` holding one root node, with a new uid: `{scenePath, root, uid}`.
- **Use:** `scenePath`, `rootType` (default `Node2D`; a Node class or a script's `class_name`), `rootName` (default the file name in PascalCase), `options {overwrite}`.
- **Edges:** an existing file is refused without `overwrite`; a replaced file keeps its uid.

### `save_scene`

- **Does:** opens a scene and saves it again, in place or to `newPath` (save-as): `{scenePath, savedTo, uid}`. In place it writes Godot's full 4.7 form; a save-as keeps the source's text (its `ext_resource` ids, its tag lines) with the new file's own header.
- **Use:** copying a scene to a new file; `options {overwrite}` for an existing `newPath`.
- **Edges:** a new file gets a new uid; saved over a file, the copy takes that file's uid.

### `add_node`

- **Does:** adds a node named `nodeName` of `nodeType` (a Node class, a script's `class_name`, a script path, or a scene path, added as an instance) and saves: `{path, type, index, instance?, script?}`.
- **Use:** `options {parent, properties, position}`: parent path from the root (default `.`), `{name: value}` set once the node is under its parent, as the editor sets them (so a Control's `layout_mode` takes 0 or 1 under a Control, is 2 under a Container and 3 with no Control parent; `anchors_preset` and a non-zero `anchor_*` need `layout_mode` 1, which is applied first), and a position among its new siblings as `move_node` takes it (default last; in 2D, sibling order is draw order). A script path (`res://Foo.cs`, `res://foo.gd`, no `class_name` or `[GlobalClass]` needed) makes a node of the script's base class with the script attached; `type` is that base class and `script` the path.
- **Edges:** a sibling name clash, a parent inside an instanced scene (an instance's own root may be the parent), and a scene instancing itself are refused; a property that does not take adds nothing. A script that does not compile or does not extend a Node class is refused, and a `.cs` script while the project's C# build fails, as `attach_script` refuses it.

### `delete_nodes`

- **Does:** deletes 1 to 100 `nodePaths`, with their children, and saves: `{deleted}`.
- **Edges:** the root, a node inside an instanced scene and a node an inherited scene gets from its base are refused; deleting an instance's root removes the instance. One refusal saves nothing.

### `duplicate_node`

- **Does:** copies `nodePath` and its subtree right after it, or last under `options.parent`, and saves: `{originalPath, newPath}`. The copy and every node it owns get fresh `unique_id`s, as the editor's Duplicate gives them; every other node keeps its own.
- **Use:** `newName`, else the node's name or the editor's serial name (`Sprite` gives `Sprite2`).
- **Edges:** instances stay instances; connections within the copy and out of it are kept, connections into it are not. The root is refused.

### `move_node`

- **Does:** moves `nodePath` among its siblings, or under another parent, and saves: `{path, previousPath, index}`. In 2D, sibling order is draw order: later siblings draw on top.
- **Use:** `options {parent, position, keepGlobalTransform}`, at least one of `parent` and `position`. A position is exactly one of `{index}`, `{before: "<sibling name>"}` or `{after: "<sibling name>"}`; a negative `index` counts from the end (-1 is last). With `parent` and no position the node goes last. A reparented node keeps its global transform unless `keepGlobalTransform` is false, and its subtree stays the scene's own.
- **Edges:** refused, with the file unchanged: the root, a node inside an instance or from a base scene (the file cannot record their move), a parent that is the node or its own child, a name clash under the new parent, an `index` out of range or a sibling name that is missing or is the node itself. `Node`-typed exports and signal connections follow the node, since the save recomputes them; `NodePath`-typed properties on other nodes are not rewritten.

### `attach_script`

- **Does:** sets `scriptPath` (`.gd` or `.cs`) on `nodePath`, replacing its script, and saves: `{path, script, previous?, kept?, dropped?, uidFilesWritten?}`. The values the previous script stored carry over as the editor carries them: a value is kept when the new script declares its name and the value's type matches (or an object fits the new export's class); `kept` and `dropped` name them.
- **Edges:** the script must compile and extend the node's class. A C# script is refused while the C# build fails. An instance's root and a node from a base scene are allowed, saved as overrides.

### `load_sprite`

- **Does:** sets the `texture` of `nodePath` (Sprite2D, Sprite3D, TextureRect, NinePatchRect, Polygon2D, or any node with a Texture2D `texture`) to `texturePath` and saves: `{path, texture}`.
- **Edges:** an image never imported is imported first by the editor's full scan, which writes `.import` and `.uid` files across the project: expect those in the diff. An image in a folder Godot does not scan (a name starting with `.`, or holding `.gdignore` or a nested project's own `project.godot`) is refused.

### `set_node_properties`

- **Does:** sets 1 to 100 `updates` `{nodePath, property, value}`, reads each back, and saves: `{results: [{nodePath, property, before, after}]}`.
- **Use:** values as `set_property` takes them, typed arrays and dictionaries included; a resource as a `res://` or `uid://` path, `{resource: path}`, `{type, ...properties}` or null; a Node-typed export as a path from the scene's root.
- **Edges:** a node from a base scene, or inside an editable instance, may be set (saved as an override); inside another instance it is refused. A non-zero `anchor_*` on a Control in Position layout (`layout_mode` 0) is refused unless the node already holds that value: set `layout_mode` 1 first (a full rect is `layout_mode` 1, `anchors_preset` 15, `grow_*` 2); the editor cannot make a Position node with anchors. Under a Container, `anchor_*`, `offset_*`, `grow_*` and `anchors_preset` are refused unless unchanged, since Godot saves none of them there: set `size_flags_*` instead. All or nothing.

### `get_node_properties`

- **Does:** reads 1 to 50 `nodes` `{nodePath, properties?, changedOnly?}` of a scene file; nothing is saved: `{results: [{nodePath, type, script?, properties} | {nodePath, error}]}`.
- **Use:** `changedOnly` for just what the scene file stores for the node; `options {prepare}`.
- **Edges:** the scene is instantiated to read it, so its scripts' `_init` runs (never `_ready`). A missing node fails its own entry alone.

### `get_node_signals`

- **Does:** lists a node's signals and the persistent connections the scene makes from each; nothing is saved.
- **Use:** before `connect_signal` or `disconnect_signal`; `options {prepare}`.
- **Edges:** connections made by `connect()` in code are not listed. `inherited: true` marks a connection from an instanced or base scene, which only that scene's file can change. A C# script's signals are missing while its build fails (`warning` says so).

### `connect_signal`

- **Does:** saves a persistent connection from `signal` on `nodePath` to `target {nodePath, method, binds?}`: `{from, signal, target, method}`.
- **Edges:** refused, saving nothing: a missing node, signal or method; an emitting node inside a non-editable instance; arguments plus binds that do not fit the method; a bind that does not convert (an array of Objects says why); a signal already connected to that method.

### `disconnect_signal`

- **Does:** removes the connection from `signal` on `nodePath` to `target {nodePath, method}`, whatever its binds.
- **Edges:** an inherited connection is refused, naming the scene whose file makes it.

### `export_mesh_library`

- **Does:** builds a GridMap MeshLibrary from a 3D scene by the editor's Import from Scene rule and writes it to `outputPath` (`.tres` or `.res`); the scene is only read: `{outputPath, items: [{id, name, shapes, navigation}], replaced?}`.
- **Use:** `meshItemNames` to keep only some items; `options {overwrite}`.
- **Edges:** every MeshInstance3D with a mesh below the root is an item named after its node; two nodes of one name make one item (`replaced`). No previews are made. A file the scene uses is refused as `outputPath`, whether directly, through an instanced scene or a resource file, or by a node an earlier `batch_scene_operations` step changed; the refusal names the file or node (`through res://cell.tscn`, `through node Grid`). A replaced `.res` keeps its uid when the project has an import cache (`.godot/uid_cache.bin`) and gets a new one in a never-imported project (a `.tres` keeps its own).

### `batch_scene_operations`

- **Does:** runs 1 to 100 scene edits on one scene in a single headless Godot and saves once: `{passed, steps, failedAt?, uid?}`.
- **Use:** any change of more than one edit: each step is `{tool, args}`, `tool` one of `delete_nodes`, `attach_script`, `duplicate_node`, `move_node`, `load_sprite`, `add_node`, `set_node_properties`, `connect_signal`, `disconnect_signal`, `export_mesh_library`, `args` that tool's own arguments without `projectPath` and `scenePath`. Later steps see earlier ones (add a node, then connect its signal).
- **Edges:** every step is checked before Godot starts. At the first failed step nothing is saved and no library written. One Godot start for the lot, so it is much faster than the tools one by one.

## Project profiles: `godot-mcp.json`

A `godot-mcp.json` beside `project.godot` sets launch defaults for every `run_project` on the folder. Top-level keys: `scene`, `userArgs`, `engineArgs`, `resolution` (`WIDTHxHEIGHT`, lowercase `x`), `quiet`, `presets`, `prepWrapper`. Each preset under `presets` takes the same keys but `presets`, plus `session` and `description` (what the preset is for; an unknown `options.preset` is refused listing each preset as `name (description)`). The file may carry `//` and `/* */` comments and trailing commas, so a value can sit beside a note on why it is set. `run_project`'s `options.preset` layers a preset over the top level, and the call's own arguments override both: `scene`, `resolution` and `quiet` are replaced by the later layer, `userArgs` and `engineArgs` append. The session name is `options.session`, else the preset's `session`, else the folder's. Parsing is strict: an unknown key, a wrong type or a bad resolution refuses the launch with the file's path and the fix. `restart_project` reuses the merged launch and does not re-read the file. The profile is not a tool and applies to `run_project` only, except `prepWrapper`.

`prepWrapper` (an array of strings: a program, then its arguments) runs the prep's processes, the C# build, its Compile-items listing and the import, through a project's own wrapper such as a gate script, for every tool that preps: launch, restart, preview and the headless tools. Each runs as the wrapper followed by the process's absolute path and arguments, from the project folder; `{log}` in any element becomes the step's log (`.godot/godot-mcp/build.log`, `import.log`) and `{ceiling}` the prep's ceiling in seconds (300). A program with a folder in it is relative to the project folder, a bare name is found on `PATH`. When the wrapper takes `{log}`, it writes that log and its own output goes to `build.wrapper.log` / `import.wrapper.log` beside it, and an import's second pass writes `import.2.log`. A wrapped process has no stall kill (a gate waiting for a slot is silent), the ceiling still holds, and a wrapper exit of 124 refuses the prep with `the prep wrapper stopped the build (exit 124); its log: …`. `prep.note` says `ran through prepWrapper (<program>)`. A malformed `godot-mcp.json` refuses any prep that runs a process.

```json
{ "prepWrapper": ["pwsh", "tools/gate.ps1", "-Log", "{log}", "-TimeoutSeconds", "{ceiling}", "-Slot", "heavy", "--"] }
```

## Worked drives

### Reproduce a UI bug and screenshot it

1. `run_project {projectPath}`: note `session`; check `prep` when the project is C#.
2. `get_ui_elements {filter: "BaseButton"}`: find the button's `path` and check `disabled` and `visible`.
3. `click {target: {element: "Main/Menu/Settings"}}`: read `errors` in the result; a handler error shows its file and line here.
4. `wait_for {condition: {node: "SettingsPanel", exists: true}, timeoutMs: 3000}`: `met: false` means the panel never appeared; `last` shows what was seen.
5. `take_screenshot {}`: look at the preview; pass the `path` to the user.
6. `get_errors {since: 0}` for warnings, then `stop_project`.

### Step physics frames and assert with `wait_for`

1. `run_project {projectPath, scene: "res://tests/jump_test.tscn"}`.
2. `frame_control {action: "pause"}`.
3. `set_property {node: "Player", property: "velocity", value: {x: 0, y: -400}}`: check `after` matches.
4. `frame_control {action: "step", count: 10, options: {unit: "physics", screenshot: true}}`: `physicsFrames` is 10; the image shows the frame after the tenth tick. The game stays paused.
5. `wait_for {condition: {node: "Player", expression: "node.position.y < 300"}, timeoutMs: 0}`: a check-once wait, accepted while paused; `met` is the assertion and `value` what the expression returned. A property equality works the same way: `{node: "Player", property: "position:y", equals: 280}`.
6. Repeat steps 4 and 5, then `frame_control {action: "resume"}`.

### Edit a scene headlessly, then preview it

1. `list_sessions`: a live session on the folder can keep running; it sees the edits only after `restart_project`.
2. `create_scene {projectPath, scenePath: "res://ui/hud.tscn", rootType: "Control"}`.
3. `batch_scene_operations {projectPath, scenePath: "res://ui/hud.tscn", steps: [{tool: "add_node", args: {nodeType: "Label", nodeName: "Score", options: {properties: {text: "0", position: {x: 16, y: 16}}}}}, {tool: "attach_script", args: {nodePath: ".", scriptPath: "res://ui/hud.gd"}}]}`: `passed: true` and a `uid`; on failure `failedAt` names the step and nothing was saved.
4. `validate {projectPath, targets: ["res://ui/hud.tscn", "res://ui/hud.gd"]}`: `valid: true`, or the first error per file.
5. `get_scene_file_tree {projectPath, scenePath: "res://ui/hud.tscn"}`: confirm the node paths.
6. `preview_scene {projectPath, scene: "res://ui/hud.tscn", options: {resolution: "1280x720"}}`: look at the image; `errors` holds anything `_ready` raised.

### Drive a gamepad menu

1. `run_project {projectPath, options: {shutOutRealGamepads: true}}`: so a pad on the desk cannot move the focus under you.
2. `get_ui_elements {filter: "Button"}`: learn the menu's buttons.
3. `gamepad_button {button: "DPAD_DOWN"}`, or `gamepad_stick {stick: "left", position: {x: 0, y: 1}, options: {release: true}}`: without `release` a second push does not move focus again.
4. `wait_for {condition: {expression: "root.gui_get_focus_owner().name == \"Options\""}, timeoutMs: 1000}`: `met: true` confirms where focus went.
5. `gamepad_button {button: "A"}`, then `wait_for` on the screen it opens.

### Record a clip around a bug

1. `run_project {projectPath, options: {record: true, dropIdle: true}}`: `recording.path` is the movie in progress. `dropIdle` keeps the clip to the action: without it the clip also holds every idle frame drawn while you were between tool calls. Leave it out when a still moment or the sound matters.
2. Drive to just before the bug. `record_mark {mark: "start"}`: note `frame`.
3. Trigger the bug with the input tools. The run is at a fixed 60 fps, so millisecond durations no longer match game time: wait on conditions with `wait_for`, not on durations.
4. `record_mark {mark: "stop"}`.
5. `stop_project`: `recording.clips` lists one `.mp4` for the pair, and the full movie is gone; `recording.error` means ffmpeg was missing or failed and `recording.path` is kept instead.

### A `batch_drive` regression check against a baseline

1. Once, in a known-good build: drive to the state, `frame_control {action: "pause"}`, `save_screenshot_baseline {name: "hud-idle", crop: {x: 0, y: 0, width: 400, height: 80}}`.
2. After a change: `run_project`, then one call:

   `batch_drive {steps: [{tool: "click", args: {target: {element: "Main/Menu/Play"}}}, {assert: "wait", node: "Hud", exists: true}, {tool: "frame_control", args: {action: "pause"}}, {assert: "property", node: "Hud/Score", property: "text", equals: "0"}, {assert: "screenshot", name: "hud-idle", maxChangedRatio: 0.001}, {assert: "no_errors"}]}`

3. Read `passed`. On failure `failedAt {index, reason}` names the step; for a screenshot failure the step's error carries the comparison, and `compare_screenshot {name: "hud-idle"}` outside the batch returns the diff image to look at.
